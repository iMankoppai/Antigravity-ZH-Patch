# 验证设计应用情况

使用已连接的 Spacefast 工具。在代码仓库中工作时，保留无关的文件和改动。

如果任务需要某个现有 Space 且其身份不明确，调用 `choose_space`。将选中的 Space 作为目标。选中并不代表批准发布或其他改动。

在执行管理操作前，阅读 [references.md](references.md) 中的 MCP 调用、审批与工作模式规则。

1. 确定团队和 Space，然后确定确切的完整源码修订版本以及相匹配的已构建预览或版本。阅读 references.md 中的设计系统（Design system）和源码编辑（Source edits）。
2. 阅读 references.md 中的团队记忆与技能（Team Memories and Skills）。获取当前标准、适用的记忆、已启用的团队技能和资源。在判定合规之前，识别过时的 `design.md` 或预览；不要将缺失的标准视为通过。
3. 在具有代表性的桌面端和移动端宽度下检查受影响的页面、组件、状态、资源和文案。将每项发现关联到已保存的规则、实现位置和渲染证据。
4. 对于包含修正的请求，修改已授权的源码、重新构建，并重复受影响的视觉检查。对于仅审查的工作，报告发现而不进行编辑。
5. 报告版本、已检查的区域、修复与复测、未解决的差距以及决策。验证不授权发布。
