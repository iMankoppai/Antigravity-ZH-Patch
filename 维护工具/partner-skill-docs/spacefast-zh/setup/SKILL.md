# 快速开始

检查连接，然后继续用户的任务。
利用用户的请求和迄今的对话。继续一项已确定的任务，不要让用户重复说明。当用户把工作带到 Spacefast 进行发布时，开始发布该工作。

如果任务不明确，提一个简洁的问题并等待。对于新的发布对话，询问：“你想构建或发布什么？”对于其他操作，只询问缺失的细节。根据其回答采取下一步。

保持回复简短。将这些说明作为参考资料。除非被询问，不要总结这些说明，也不要给出 Spacefast 的概述或功能列表。仅在当前步骤需要时提及设置、凭据、共享或故障排查。

仅凭设置本身，并不授权发布、更改设置或创建监控。
保留用户已为其任务给出的任何授权。连接 Spacefast 并不需要他们重复授权。

## 检查连接

On-Device MCP 使用现有的本地 Spacefast 登录或已配置的服务凭据。当账户读取需要身份验证时，遵循其返回的登录说明；不要告诉用户本地 stdio 连接需要主机 OAuth。

对于位于 `https://mcp.spacefast.com` 的托管 MCP，使用该连接已配置的身份验证。直连的托管连接使用主机的 OAuth 控件；CLI 代理使用其现有的 CLI 登录。如果身份验证失败，引导用户通过该方法重新连接。
如果工具不可用，引导用户使用主机已配置的 Spacefast 连接控件。
不要在聊天中索要令牌。在读取成功之前，不要报告连接可用。

通过 Spacefast API 工具读取已连接的账户：

每个 Spacefast API 操作都有一个以其操作 ID 命名的 MCP 工具，例如 `getAccount`。阅读其输入 schema 以及任何公布的输出 schema，然后直接发送其声明的 JSON 输入；主机可以通过其自身的工具搜索找到该工具。仅使用此连接所公布的工具。在生成改动前完成只读准备。保留失败的结果和后续说明，用一次读取验证每一次成功的写入，并直接使用返回的图片和文件。

1. 阅读 `getAccount` 的契约，并以 `{}` 调用它。
   对于用户提供的引用，在顶层添加可选的 `teamRef` 或 `spaceRef` 字段。
2. 在工具回执中保留完整的操作结果。检查其返回的状态和
   `result.ok`。保留失败的结果及其后续操作。一个携带
   操作结果的已完成回执，其账户负载位于 `result.data.data`。
3. 仅报告主体或账户名称，以及相关的团队名称和 ID。
   仅当可选引用值的 `status` 为 `resolved` 时，才使用这些值。
   不要返回完整的账户负载或凭据。

如果该连接的工具不可用，请在检查账户状态前重新连接。
来自其他服务器的工具不属于此连接。

用一句话简短确认已连接的账户或服务身份。服务连接不是其创建者的个人账户。
复用对话中已建立的 Space。普通的发布不需要 Space 选择器。

## 按需使用主机功能

仅当任务需要且主机或已连接的服务器公布了这些功能时才使用：

- Space 库（Space Library）和提及选择器可帮助用户选择一个 Space。
- 如果 `choose_space` 可用，在需要选择时使用它。尊重取消操作。
- 插件设置、HTML 预览和事件订阅取决于主机支持。
  不要仅因为本技能描述了这些功能就承诺它们。

选中的 Space 提供上下文。它本身并不授权写入。
