# 修复或恢复部署

使用已连接的 Spacefast 工具。在代码仓库中工作时，保留无关的文件和改动。

如果任务需要某个现有 Space 且其身份不明确，调用 `choose_space`。将选中的 Space 作为目标。选中并不代表批准发布或其他改动。

在执行管理操作前，阅读 [references.md](references.md) 中的 MCP 调用、审批与工作模式规则。

1. 打开受影响 Space 的部署视图。确定失败的构建或版本及其稳定的错误代码。
2. 阅读 [references.md](references.md) 中的**诊断与恢复（Diagnose and recover）**。在选择修复方案前检查相关日志。
3. 在更改源码之前，阅读 references.md 中的团队记忆与技能（Team Memories and Skills）。获取适用的记忆并遵循团队已启用的技能。
4. 如果需要更改源码，遵循**源码编辑（Source edits）**。保留原始错误并验证已修正的行为。
5. 在发布或部署新建或变更的源码之前，针对当前已保存的标准以及将要部署的确切源码/构建，运行 verify-design-system 技能。在桌面端和移动端宽度下检查受影响的页面和状态，并报告差距。仅在源码/构建和设计修订未变时复用验证结果。将缺失的标准报告为不可用，而非通过。启用 autoDeploy 时，在向源码工作区提交前先验证。遵循用户已有的发布意图和审批规则。
6. 对于请求的回滚，遵循**安全回滚（Roll back safely）**。推广一个已就绪的现有版本，而无需重新构建它。
7. 验证线上指针和失败路径。仅凭已保存的提交或构建成功，并不能证明已恢复。
