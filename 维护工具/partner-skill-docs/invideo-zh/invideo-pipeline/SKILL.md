# 一次制作多个视频

先阅读 `/invideo`。

## 从简要说明开始

获取整张表，而不是样本行；样本行永远是最漂亮的那一行。

## 让它奏效的关键

在规模化时，你不再编辑视频，而是开始编辑生成视频的系统。每位观看者只看到属于自己的内容，因此批次的好坏取决于它最差的那一行：溢出的名字、空字段、"1 lessons"。把功夫花在数据的边缘，而不是中间。

- 先手动剪辑三行差异很大的数据。它们之间变化的部分就是变量；其余部分锁定。
- 针对观看者做过、制作或获得的内容进行个性化。仅有名字只是装饰。
- 修正模板或数据，永远不要手工修某一个视频。

## 技巧

- **锁定与自由。** 锁定故事、节奏、音乐、字体和颜色。让数据去改变名字、数字、图像、语言和钩子。如果某个值冲淡了关键时刻（"1 lesson"上方的彩带），那一行应换用不同的场景，而不是更小的字号。
- **最差的行。** 在开始批次前，先运行最难的行：最长的名字、空单元格、全大写、其他文字、零和一、宽槽中的竖版照片、白色背景上的白色 logo。每一行都应看起来是经过设计的，而不仅仅是没出问题。
- **文本。** 先留出空间，然后换行，再缩小到下限，最后切换布局。绝不要截断名字，也不要把名与姓分开。停留时间跟随字数；多余的时间放进停留的背景，绝不放进踩音乐的那一拍。短标签在翻译中膨胀最多。
- **回退。** 缺失数据得到的是重写的句子（"欢迎加入"），而不是"Hi Friend"。数据稀少的观看者得到的是一段关于开始、更温暖更短的剪辑，绝不只是一个令人难过的数字。当错误比缺失更糟时，跳过该行。
- **声音。** 整条线用一个声音。把名字拼接进另一个声音是最容易暴露的破绽。固定名字和品牌术语的读法。
- **变化。** 变体是表亲，课程是同胞。大力改变钩子和开头几秒，保留品牌脉络；换个字幕不算变体。轮换两三种布局，让整套内容永不显得是机器制作的。你的厌倦不是观看者的厌倦。
- **检查。** 从极端情况试点五到十行，获得批准后再运行其余部分。重复出现的缺陷会中止整个批次。扫描变化最大的时刻的静帧、每一个分支，以及长度上的异常值。以每一位对应观看者的身份观看其中几个。
- **命名。** 根据数据命名文件：谁或什么、格式、版本。为每一行提供一个稳定的键，这样重跑时会跳过已完成的行，也不会有人收到两个视频。

## 脚本化运行

含确切命令的实操脚本：https://docs.invideo.io/how-to/ci-and-servers 和 https://docs.invideo.io/how-to/developers/csv-to-videos（markdown：加 `.md`）。

- 使用带 `--json` 的 CLI，并读取 JSON。
- 为每次生成提供各自的 `--idempotency-key`（该行的 id 和步骤，如 `row-42-voice`），这样重跑时会找到之前的生成结果，而不是重新生成。
- `invideo status <urls…> --wait` 会跟踪生成和导出，直到它们完成。
- 会话保存在登录的那台机器上（钥匙串或密钥环，否则为 `~/.config/invideo/credentials.json`）。对于 CI，使用持久化的 runner，在其中有某人曾用 `INVIDEO_NO_BROWSER=1 invideo auth login` 登录过一次。

## 一个项目中的多个 agent

注册一个表明你角色的名字，只负责一个部分，每次操作前阅读收件箱和时间线，并为用户撰写每一处更新。技巧：`references/collaborate.md`。

## 按类型

| 视频 | 重点 |
|---|---|
| 外呼 | 开头是来自发送者的几秒真实画面，然后是就潜在客户自身问题的共享正文。 |
| 课程批量 | 每节课少于六分钟。将第一课锁定为基准；统一响度，统一外观。最后，把第一课与最后一课并排观看。 |
| 批量订单 | 先试点最简单和最难的项。每条客户备注都写入同一份风格表，其余内容都对照它检查。 |
