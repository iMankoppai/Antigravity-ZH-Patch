## 每次修改

- [ ] 记录 Git 初始状态，保留未提交改动和本机证据。
- [ ] 记录客户端版本、管理器版本、内核版本和问题触发步骤。
- [ ] 判定固定 UI / 动态 UI / 拆分节点 / 内容，保存最小证据。
- [ ] 先增加失败用例；同时增加同词出现在正文或目标中的保护用例。
- [ ] 词库变动通过 JSON、重复键、占位符、术语与保留词审核。
- [ ] 运行时改动通过语法、当前浏览器回归、动态更新和恢复检查。
- [ ] 必要时更新内核版本与测试期望值；从实际内容计算词条数。
- [ ] 用规范入口生成 bundle，`--check` 通过。
- [ ] 检查 Diff，不引入意外词库或包装器变化。
- [ ] 在受影响真实场景复验；无法触发的场景记“未测试”。

## 每次发布

- [ ] 当前源码必需检查全部通过；旧适配测试不冒充当前测试。
- [ ] 编译到独立候选目录，保留现有正式产物。
- [ ] 检查候选程序启动、版本和实际内嵌资源。
- [ ] 临时 ZIP 可解压、CRC 正确、文件集合与中文名正确。
- [ ] ZIP 中 EXE 与候选 EXE 字节/SHA256 一致。
- [ ] 清单、版本元数据、README、发布文件名一致。
- [ ] 新包验证后再替换正式包；清理仅属于本次的暂存目录。
- [ ] 安装前核对客户端版本、归档哈希、对应备份和进程状态。
- [ ] 安装归档结构正确；实际变更等于计划白名单。
- [ ] 安装 bundle 与本次发布资源一致。
- [ ] 安装后完成必需现场验收；恢复流程经过匹配版本验证。
- [ ] 发布判定明确为“可发布 / 不可发布 / 待验收”，说明未测项。
- [ ] 外部推送或发布获得本次所需授权；本清单不授权 `git push`。
