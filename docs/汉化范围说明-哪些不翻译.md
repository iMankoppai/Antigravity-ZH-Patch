# 汉化范围说明：哪些内容故意不翻译

编写日期：2026-10-13。配套文件：`work/2-23-0-qa-report.md`（2.23.0 质量巡检报告）。

这份文档解释一件事：**界面里偶尔还能看到英文，为什么有些是"故意保留"，不是漏译。**

## 一句话原则

汉化只翻**界面固定文案**（按钮、菜单、提示、状态文字），不翻这三类东西：

1. **内容**——AI 写的正文、你自己输入的对话、项目名、文件与命令、服务端下发的公告
2. **专名**——产品名、模型名、主题名、快捷键
3. **程序内部标识**——代码里的枚举名、设置键、图标名（这些本来就不会显示给用户）

翻错这三类的后果比不翻更糟：改坏程序逻辑、把用户的内容改掉、或者让同一控件的两处文字自相矛盾。

## 具体清单（都能在报告里复核）

| 界面里看到的英文 | 它到底是什么 | 为什么不翻 |
| --- | --- | --- |
| `BASELINE`、`CAPABILITIES`、`DEVELOPER`、`FRAMES`、`HUB`、`TRANSCRIPT` | 程序内部的**枚举名**（代码里用 `Enum[HUB]="HUB"` 这种形式传值） | 只用于程序内部判断，不会显示在界面上；翻译等于改代码 |
| 模型列表里的 `Notice`、`NEW` 徽标 | **服务端下发的模型配置**（`tagTitle` 字段）生成 | 属于内容：随服务器变化，本地词库追不上，也不该追 |
| `tokens (` 显示为 `Token (` | 词库既有术语约定：`Token` 保持英文（`Tokens`→`Token 数`、`Token Usage`→`Token 用量`） | 这是术语统一，不是漏译；自动巡检只因"译文无汉字"才把它列出来 |
| 你自己的项目 / 工作区名称（侧边栏与标题栏里显示的那串）、菜单栏 `Antigravity`、模型名 `Gemini 3.8 Flash High` | 你自己的工作区名、品牌名、模型名 | 用户内容 / 专名，翻掉反而无法辨认 |
| 词库里 516 条键在"前端文件"里搜不到 | 前端文件只是界面的一部分；权限申请弹窗、MCP 描述、输入框占位等文案来自**语言服务器/服务端资源** | 搜不到 ≠ 失效。只有**逐版本对比后消失**的串才说明官方改了词，那批新写法已经补进词库；盲目删这 516 条会真的丢翻译 |

## 怎么判断"是界面文案还是内容"

1. 先在**官方前端文件**或服务端资源里找到这个串的出处，看它是被谁渲染的；
2. 再看它所在的 DOM 位置：在正文（AI 回复、你的消息、思考过程）、代码块、终端、文件名里 → 内容，不翻；
3. 在按钮、菜单、标签、提示、状态行里 → 界面文案，进词库；
4. 拿不准的**保留原文**并记录，宁可少翻一处，也不误伤内容。

## 反过来：真正的问题长什么样

巡检里判定为"必须修"的是这三类，跟上面完全不同：

| 真问题 | 例子 | 后果 |
| --- | --- | --- |
| 死词条 | 词条键里带了前后空格（`"Zipping "`），而程序查表前会去掉空格 → **永远命不中** | 该翻的地方一直没翻，还以为已经覆盖了 |
| 逐词误译 | 模型名 `Gemini 3.8 Flash High` 被译成 `Gemini 3.8 Flash 高`，同一按钮的无障碍标签却还是 "…High" | 界面自相矛盾、专名被改 |
| 动态模板漏收录 | `Agent permissions preset selector, current: X` 这类带变量的整句没进词库 | 只有这一处永远保持英文 |

## 如果你觉得某处该翻

发一张截图 + 那处文字在界面上的位置（哪个面板/按钮）。判断流程同上：先确认它是界面文案还是内容，再决定是进词库、加规则，还是列入保持原文的清单。
