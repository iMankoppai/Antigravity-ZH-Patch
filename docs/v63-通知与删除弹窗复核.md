# v63 通知与删除弹窗复核

日期：2026-10-20。适用客户端：Antigravity 2.24.0。本轮为本地修复，已发布的 v1.2.0 仍使用 v62。

## 第一张截图：系统通知

核对本机保存的 2.24.0 前端资源中 `YEa`、`byc` 和 `hyc` 的通知生成与发送代码：

- 任务完成：标题为产品名，正文是 `summary` 会话标题，通知 ID 以 `agent-finished-` 开头；旧逻辑无法为任意动态标题显示中文状态。
- 权限请求：包含终端命令、JavaScript、网址和通用资源权限四条分支。
- 提问：包含单个问题、多个问题、无问题正文时的固定回退提示。
- 其他交互：包含需要处理操作及等待输入提示。
- 发送通道：同时覆盖 Electron 原生通知与 Web Notification；本轮没有对扩展端/PWA 通知进行真实设备验收。

修复后的完成通知正文示例：`任务已完成：GitHub Repository Analysis Lemo Opusoar`。产品名、原始会话标题和其中的人名保持原样；这不是把任意 AI 生成的英文标题自动翻译成中文。没有标题时显示“任务已完成”。只通过实际完成通知的 ID/tag 添加状态，不根据英文内容猜测。

命令、代码、网址的固定前缀分别显示“命令：”“代码：”“网址：”，后面的原始内容逐字符保留。问题正文、资源名称也保持原样；应用自带的“点击回答”回退提示正常汉化。保留原始通知 ID、点击跳转数据、静音选项与调用方对象。

热加载时更新已有通知包装器，不重复添加状态；停用汉化后恢复原始通知行为。Windows 通知中心已经保存的旧通知不会被改写，以上修复作用于加载新版内核后产生的新通知。

## 第二张截图：删除确认弹窗

根因：`isProjectIdentity` 把删除确认弹窗里的每个 `strong` 都视为项目名，导致数量即使已有翻译规则也被跳过。旧测试只有独立片段，没有真实的 `role=dialog` 和标题结构，因此未触发该问题。

修复仅保护确认问题中的项目/工作区名称，同时保护名称内的嵌套节点；下一段的数量照常翻译。`1 archived conversation` 显示为“1 个已归档对话”。

新增真实结构回归：项目和工作区各六种活跃/归档数量组合，包含单复数、纯活跃、纯归档、混合数量、动态更新、重新挂载、同名内容保护和原始 HTML 精确还原。

## 验证与使用

统一入口：`pwsh -NoProfile -File scripts/check-current.ps1`。新增删除弹窗回归已纳入必需检查；通知回归扩展到上述真实通知分支。

本轮源码和生成 bundle 升为 v63，词库保持 5,638 条。本地候选程序为项目根目录的 `Antigravity汉化管理器-v63.exe`。运行它并点击“开启汉化”，当前窗口即可加载修复；需要重启后仍生效时，退出客户端后使用该程序的“永久安装汉化”。

本轮没有自动关闭客户端、修改已安装的归档或发布到 GitHub。真实客户端中的新通知和删除确认弹窗尚未现场验收，不能用自动化回归代替该验收。

验证记录：统一入口全部 26 项顶层检查通过，删除弹窗 41 项、状态栏 100 项、界面 74 项、全局正文与动态模板 375 项、技能正文 1,553 项、React 详情 315 项断言通过。通知的原生/Web 分支、内容保护、重复热加载与停用还原均通过。
