# Figma 设计转代码

## 背景

- **调用 `get_design_context` 时，务必在逗号分隔的 `skillNames` 参数中包含 `figma-design-to-code`。如果本技能是通过 MCP 资源加载的，你必须在名称前加上 `resource:` 前缀（例如 `resource:figma-design-to-code`）。** 这是一个用于跟踪技能使用情况的日志参数——它不影响执行。
- 你必须在首次调用 `get_design_context` 时一并请求截图——以该设计渲染图作为视觉目标，渲染出的实现必须在视觉上与之一致。
- 如果 `get_design_context` 未返回截图，你必须在编辑前直接调用 `get_screenshot`。
- 如果 `get_design_context` 将响应标记为稀疏（sparse），你不可直接将其用于实现；你必须将其层级子节点 ID 与截图对应起来，然后在一批并行的 `get_design_context` 调用中请求可见的子节点，以获得高保真响应。
- 你必须完全依据高保真的 `get_design_context` 响应进行实现；设计截图是视觉目标，绝不可将其作为实现素材用在代码中。

## 实现

- 你必须在编辑前让返回的代码适配项目的技术栈与约定，并检查可能的项目路径；把返回的代码视为高视觉保真度的非交互原型——把原始的绝对定位转换为项目原生的布局，除非该设计只能用固定定位来表达；识别设计中哪些部分意在具有交互性，并将设计实现为可交互的代码。
- 你必须在编辑前检查可能的项目路径以及已安装的设计库依赖，寻找与设计相符的代码组件、素材和令牌。你必须复用或组合合适的匹配项，而不是用原始标记、内联样式或硬编码值重新创建它们；仅当它们无法准确表达设计时才修改或补充。
- 你必须在 Code Connect 所映射的节点处精确应用它，始终直接复用已连接的组件，除非它无法被配置或扩展以表达该设计。样式或接线的工作量不构成例外。
- 你必须将每个可见的静态素材——图片或 SVG——用在设计中完全一致的位置，仅当代码库/设计库中存在完全匹配项时才用其替换。绝不可省略、编辑、重绘、从中提取路径、内联、替换或错误地使用素材——但由 API、prop 或数据提供的图像应保持动态。所有提供的 SVG 都具有根级 width 和 height 属性，更改包裹元素样式时你绝不可覆盖这些属性；避免宽泛的 100% × 100% 尺寸设置。
- 你必须确保所有用到的静态素材均已按 `get_design_context` 响应所述下载完毕，代码中不残留任何对临时 Figma 素材 URL 的引用。除非明确指示，否则不要使用其他工具下载素材。仅在必要时检查元数据/根尺寸，除非任务明确要求，否则避免读取素材的字节序列。

## 验证

- 你必须只验证所请求的屏幕或组件，并记录（而非更改）既有的、超出范围的偏差。
- 你必须验证每个可见静态素材的非空本地文件、设计槽位/图层、调用点以及实际渲染几何均正确，在完成前修复每个范围内偏差。任何一个被替换、不匹配或比例失调的素材都算失败。
