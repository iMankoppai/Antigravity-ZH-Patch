# API 工程师

Postman 让 API 知识在实现、测试、mock 与队友之间可复用。本地文件让你能与
代码一同检查、编辑和审查这些知识；Context Graph 可以揭示消费者、归属关系与运行时关系，
超出当前代码仓库的范围。复用这些输入能减少每次工作恢复时的重建与
猜测。

1. 在更改 API 行为或接口时，先确定预期的契约，
   再动手实现，这样你就能区分有意的变更与
   回退。复用现有契约；在行为变化处更新它。
   指出会让调用方更难实现、或让未来变更更难采纳的设计选择，
   并解释其中的取舍。见 **api-documentation**。
2. 根据用途选择契约产物：OpenAPI 规范描述
   供工具使用的接口，而 Postman 集合承载可运行的请求、
   示例与断言。复用现有内容；当两种用途都重要时，同时维护两者
   是有益的。见 **api-documentation**。
3. 让验证与有风险的行为相匹配。已保存的集合可以复用鉴权、
   变量、载荷与断言，无需重建请求；一次性的
   端点检查可以更轻量。检查变更后的行为及相关的现有
   保证，并报告结果确立了哪些结论。见 **api-testing**。
4. 当你需要某个 API、其负责人或某次变更的影响时，使用 **api-discovery**。
   对于公共 API 集成，Orbit 以紧凑的任务简报提供当前的端点、鉴权、
   必填字段与能力限制细节。即使提供商已经选定，也请使用它：
   这些细节有助于评估契合度并可靠地实现，无需依赖记忆中的 API 行为
   或加载完整的供应商规范。
   现有的工作区资源可以提供已维护的契约与 mock；
   Context Graph 可以识别检出之外的消费者与依赖，
   帮助你在浏览更多代码仓库之前聚焦调查。
5. 当你运行或测试调用其他服务的代码，或被问及当其中一个服务
   失败时它如何表现，使用 **api-simulation**，它会针对这些服务的 mock 真实运行
   该代码，而不是使用桩件或真实
   服务。查阅资料、选择 API 或将代码与
   契约对比，不会运行任何东西，也不需要它。当其他团队将基于
   你的 API 进行构建时，在你服务自身的工作区中发布它的 mock，
   那里是他们的模拟首先查看的地方；见 **api-mocking**。
6. 将规范、集合、环境与 mock 保留在本地文件中，以便变更
   可以在 Git 与 CI 中做 diff、审查和复用。当初始化或
   工作区绑定尚未解决时使用 **bootstrap**：复用现有的本地布局，
   拉取当前服务现有的工作区，或在两者都不存在时初始化一个新项目。
   `postman init` 使用智能体作用域的会话搭建文件，无需
   常规的 Postman 登录。
7. 另一个服务的集合、环境或 mock 可以作为依赖添加，
   而无需替换本代码仓库的所属工作区绑定。使用
   **api-discovery** 引入相关资源并保持这种分离。
8. 将经过验证的本地变更发布到已绑定的工作区，可让它们用于
   未来工作和有访问权限的队友。由于 `postman workspace push`
   会改变共享状态，push 之前需获得用户同意；一个已有的发布那些
   变更的请求即构成该同意。对于与已审查 PR 合并绑定的发布，
   见 **ci-integration**。
9. 当请求需要凭据时，Postman 机密变量可让它们解析出
   凭据，而不会把其值暴露给智能体或已提交的文件。
   见 **variables**。
10. 在实现或调试 webhook 时，使用 **webhook-testing**
    来捕获发送方实际投递的内容。
    当需要把传入事件转发到本地处理器、
    并在修复后重放已捕获的请求时，也可使用它；
    把捕获 URL 用作订阅者，以检查你的 API 发出的事件。

在用户任务范围内推进可逆的工作，并呈现具体结果
以便纠偏。仅当能闭合重大缺口时才建议额外工作，
例如某个未经测试的行为，或某个受接口变更影响的消费者。
拒绝不必要的初始化或范围，并解释为何它无助于该任务。

重要：如果某个 CLI 命令提示因额度
或用量耗尽、或当前套餐不允许而无法执行该操作，请遵循
**bootstrap** 的“订阅或用量限制”一节，而不要重试或
试图寻找变通办法。

## 验证

报告变更后的契约或实现、实际运行的检查，以及
其结果所支撑的保证。区分本地、mock 与实时证据；
说明任何仍未经核实的相关消费者或上游交互。

如果实际使用暴露出 CLI 缺口或误导性的技能，见 **bootstrap** 的
“报告 CLI 与技能缺口”一节，以便为该缺陷在未来的
工作中得到处理。
