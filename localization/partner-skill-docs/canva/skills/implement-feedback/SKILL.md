# 从反馈到成品

一份演示文稿已进入审阅——利益相关者在各张幻灯片上留下了零散的评论。此技能读取每个线程，总结审阅者实际想要什么，直接进行明确的更改，并将任何含糊不清的事项标出以供人工决定。

## Canva 编辑 API——你能做什么和不能做什么

在分诊反馈之前，你**必须**了解这些约束。这能避免就 API 无法实现的更改与用户来回浪费。

### API 能做（通过 `perform-editing-operations`）

- **文本内容**：替换整个文本元素（`replace_text`）、查找并替换子串（`find_and_replace_text`）
- **文本格式**：字号、字重（粗体）、样式（斜体）、文本颜色、文本对齐、行高、文本装饰（下划线）、删除线、链接、列表格式
- **媒体**：替换图像/视频（`update_fill`）、插入新图像/视频（`insert_fill`）、删除元素（`delete_element`）
- **布局**：重新定位元素（`position_element`）、调整元素尺寸（`resize_element`）
- **元数据**：更新设计标题（`update_title`）

### API 不能做

- 更改字体家族/字样——仅支持大小、字重和样式
- 添加新文本元素——只能插入媒体（图像/视频），不能新增文本框
- 更改背景颜色或渐变
- 添加、移除或重排页面/幻灯片
- 修改动画或过渡
- 更改元素不透明度（新插入的填充除外）
- 组合/取消组合元素
- 修改形状（颜色、边框等）——只有形状内的文字可编辑

### 分诊规则

当某条评论请求“不能做”清单中的东西时，将其归类为**需要手动操作**。不要纠缠于该限制——只需在摘要中注明并继续。这些都是正常的；大多数设计审阅都会混合 API 支持的更改和手动更改。将细节留到末尾的手动更改清单（步骤 7）。

## 工作流

### 步骤 1：解析设计

- 若用户提供短链接（`canva.link`），调用 `Canva:resolve-shortlink` 获取设计 URL
- 若用户提供完整 Canva URL，从 URL 中提取设计 ID
- 若用户直接提供**设计 ID**（通常以 `D` 开头，例如 `DABcd1234ef`），将其作为 `design_id`；**不要**对原始 ID 使用 `Canva:search-designs`
- 否则询问设计 ID 或链接

### 步骤 2：读取所有反馈

- 用设计 ID 调用 `Canva:list-comments` 获取每个评论线程
- 对每个有回复的线程，调用 `Canva:list-replies` 捕获完整对话
- 调用 `Canva:get-design-content` 读取每一页当前的文本

### 步骤 3：分诊反馈

将每个评论线程归类为以下类别之一：

- **可操作**——API 支持且你能合理诠释的更改。运用你的最佳判断——若评论说“让标题更有冲击力”，把它改写得更具冲击力，而不是标记为含糊。若评论说“修正间距”，查看设计内容并做出合理调整。仅当你确实无法确定审阅者的意图时才上报用户（例如两位审阅者直接矛盾，或评论引用了你在设计中找不到的东西）。
- **需要手动操作**——审阅者想要 API 做不到的东西（字体家族更改、新文本元素、背景更改、页面重排等）。在摘要中简要注明——完整细节放入手动更改清单（步骤 7）。
- **已解决**——已处理、明确标记完成，或是正面确认（例如“LGTM”、“looks good”）

向用户呈现按类别组织的摘要：你计划更改什么、需要澄清什么、必须手动完成什么，以及你跳过什么。

### 步骤 4：获取用户批准——仅一次

- 呈现计划并等待用户批准
- 若用户想调整，更新计划并再次确认一次

**这是整个工作流中唯一的确认点。一旦用户同意，就开始。**

### 步骤 5：应用并提交更改

**不要再次询问用户。** 他们已批准。立即按顺序执行以下全部：

- 调用 `Canva:start-editing-transaction` 开始编辑会话
- 调用 `Canva:perform-editing-operations` 进行每项已批准的更改（尽可能将所有操作合并到单次调用中）
- 调用 `Canva:commit-editing-transaction` 保存——不要问“我可以提交吗？”或“准备好保存了吗？”
- 向用户展示编辑响应中的缩略图作为确认

### 步骤 7：呈现剩余的手动更改

在提交后（或若没有可用的 API 支持更改），呈现一份清晰的清单，列出所有仍需在 Canva 编辑器中手动完成的事项：

```
## Changes to make manually in Canva

1. **Slide 3 — Change heading font to Montserrat**
   Reviewer: @Sarah | Why: API cannot change font family
   → Open slide 3, select the heading, change font to Montserrat

2. **Slide 7 — Add a new text box for the disclaimer**
   Reviewer: @James | Why: API cannot add new text elements
   → Add a text box below the chart with: "Source: Q3 2025 internal data"

3. ...
```

包含幻灯片编号、要更改什么、谁提出的，以及分步说明，以便用户能快速完成清单。

### 步骤 8：解决评论线程

- 提交后，对每个可操作的线程调用 `Canva:reply-to-comment`，注明更改了什么
- 对于“需要手动操作”的线程，回复注明作为最接近替代方案做了什么，以及仍需手动处理什么
- 这会闭合反馈回路，使审阅者能看到他们的评论已被处理

## 规则

- 乐于助人，而非谨小慎微——宽容地诠释反馈，尽你所能做出更改，而不是将其标记为“含糊”而放弃。用户总能在批准步骤中拒绝你的更改。
- 仅当你确实无法弄清意图时才上报用户——两位审阅者直接矛盾，或评论引用了你在设计中找不到的东西
- 当审阅者意见不一致时，呈现双方观点，让用户决定
- 展示计划更改的摘要并等待**一次**批准——之后，无需进一步确认地执行一切
- **绝不**问“我可以提交吗？”、“准备好保存了吗？”，或任何变体——用户的初始批准覆盖整个编辑并提交流程
- 手动更改是正常且预期的——不要过度解释或为 API 限制道歉，只需将它们纳入清单
- 批量操作：使用单次 `perform-editing-operations` 调用并包含多个操作，而不是每处更改一次调用
