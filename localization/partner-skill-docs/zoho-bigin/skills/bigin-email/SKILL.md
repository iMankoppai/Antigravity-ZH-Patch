# 从 Bigin 发送邮件

你向 Bigin 记录发送邮件。你无法读取邮件历史；若用户询问过去的邮件，请如实告知。

## 1. 目标记录

- 你需要目标**记录 ID** 和模块：`Contacts`、`Accounts` 或 `Pipelines`（交易）。
- 复用本次对话中的当前记录。否则通过 `bigin-read`（搜索）解析它。若有多个匹配，询问是哪一个；切勿自动选择。
- 从记录中读取收件人的邮箱和全名。若没有邮箱，或 `Email_Opt_Out` 为 true，则停止并告知用户。

## 2. 发件人

每次对话调用一次 `Bigin_getConfiguredFromAddresses` 并缓存结果。除非用户指定其他经验证的发件人，否则使用 `default = true` 的条目。切勿猜测发件地址；Bigin 会拒绝未列出的地址。

## 3. 内容

- 每封邮件都需要**同时**具备主题和内容。
- 若用户在对话早些时候已草拟，则逐字复用。切勿要求其重复。
- 否则根据用户请求和记录上下文（交易名称、阶段、相关的最新备注），以用户的口吻草拟。省略用户未提及的内部备注和数字。
- **已保存的 Bigin 邮件模板无法通过此连接发送。** 若用户要求使用某个模板，请如实告知，并提议在此处草拟邮件（他们可粘贴模板文本）。

## 4. 载荷

| 字段 | 值 |
|---|---|
| `from` | 第 2 步中的 `{email, user_name}` |
| `to` | `{email, user_name}` 的数组（最多 50 个）。`cc` 和 `bcc`（各最多 50 个）仅在用户要求时使用。 |
| `subject`、`content` | 两者均必需 |
| `mail_format` | 默认 `html`；若用户想要纯文本则为 `text` |
| `reply_to` | 仅在用户要求使用不同的回复地址时 |
| `schedule_time` | 带偏移的 ISO 8601，仅在用户明确要求定时发送时 |

`data` 每次调用**只包含一封**邮件，从路径中的记录（`module_api_name` + `id`）发送。向多个记录发邮件意味着每个记录一次调用。

## 5. 发送：一道关卡

- **尚未批准：** 展示 **From / To / Subject / Body**、任何定时时间，以及将记录到哪条记录上，然后询问 **“Send it — YES or NO?”**
- **已批准：** 若用户已批准该确切草稿，或在收件人和内容就绪时说“发送”/“继续”，则直接调用 `Bigin_sendEmails`，无需再次询问。
- **批量：** 对于超过 5 个收件人记录，在发送前列出全部并重述数量。

之后，清楚地确认发送给了谁（若已定时，还包括何时）。通过 `bigin-write` 提议一个跟进任务。
