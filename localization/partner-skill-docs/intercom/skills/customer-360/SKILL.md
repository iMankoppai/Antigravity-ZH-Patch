# 客户 360

通过汇总整个 Intercom 工作区的数据，生成全面的客户画像。

## 工作流

### 第 1 步：识别客户
- 解析用户输入中的邮箱、姓名或公司
- 使用 `search_contacts` 查找联系人（按邮箱最可靠）
- 如果给的是公司名称，则按邮箱域名搜索联系人
- 使用 `get_contact` 获取完整画像（属性、标签、细分、公司）

### 第 2 步：收集对话历史
- 使用 `search_conversations`，筛选到该联系人的对话
- 分页获取所有对话（不只是第一页）
- 对于最近/最相关的对话，使用 `get_conversation` 获取完整会话串

### 第 3 步：构建画像
生成一份 markdown 画像，包含以下章节：

#### 联系人摘要
- 姓名、邮箱、角色（用户/潜在客户）、公司
- 位置、时区、最后活跃时间
- 套餐/层级（如果可通过自定义属性获得）
- 标签和细分

#### 对话历史
- 对话总数
- 表格：ID | 主题 | 状态 | 渠道 | 日期
- 突出显示任何当前处于开放/暂缓状态的对话

#### 关键主题
- 各对话中的常见话题
- 反复出现的问题或功能请求
- 情绪信号（升级、正面反馈）

#### 时间线
- 重要交互的按时间顺序列表
- 从首次接触 → 最近活动

#### 未结事项
- 未解决的对话
- 待处理的问题或后续跟进

### 第 4 步：呈现并提供后续步骤
- 呈现画像
- 主动提出深入查看任何对话
- 主动提出搜索相似客户（同一公司、相同问题）

## 最佳实践
- 始终引用对话 ID，以便用户能在 Intercom 收件箱中找到它们
- 注明数据的新鲜度 —— 自事件发生以来状态可能已改变
- 如果该联系人有大量对话，总结最近 10–15 个并注明总数
- 处理联系人存在但没有对话的情况

## 故障排查

### 未找到联系人
症状：对提供的邮箱或姓名没有结果。
解决方案：检查是否有拼写错误。尝试按邮箱域名搜索以找到相关联系人。请用户确认标识符。

### 对话过多
症状：联系人有 50+ 个对话，完整分析不切实际。
解决方案：聚焦最近 10–15 个对话。对较早的对话按主题而非逐个总结。注明总数。
