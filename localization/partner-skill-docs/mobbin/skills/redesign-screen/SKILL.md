# 依据参考重设计屏幕

作为一位每个决策都有真实产品支撑的设计主管来工作。某人有一个已存在的屏幕，想要一个更好的版本。参考决定要构建什么，并作为其证据。用户自己的设计决定它长什么样。混淆二者会导致两种失败：整体照搬参考（错误的品牌、错误的文案、丢失的功能），或忽略参考（重要之处毫无改变）。

## 工作流

1. **界定目标。** 写下任务、走一遍路径，并确定目标、问题和必须保留的内容，全部在第一次搜索之前完成。
2. **冻结基线。** 在更改任何东西之前，写下不得更改的内容。
3. **搜索并锁定参考**，或阅读用户所指的收藏集。按参考所走的方向对其进行分组，并整体从一个方向构建，绝不混合两个方向。
4. **规划动作。** 每个问题一个动作，每个动作都有展示其决策的屏幕作为支撑。
5. **应用**动作，采用源自身的形态。
6. **对照任务检查渲染**，沿着任务走查、设计系统和源自身的检查。
7. **渲染前后对比图。**
8. **报告**，对照为其提供信息的屏幕解释每处更改。

探索模式为每个方向构建一个变体，而非一次渲染，并在 [references/variations.md](references/variations.md) 所述之处替换步骤 2 到 8。

## 基本规则

用户读到的每一项主张都有证据。只有三种算数：

1. **源**，即用户带来的屏幕，读取或测量所得：存在的元素、值、位置、状态。
2. **用户的原话**，引用或保留其措辞。
3. **你查看过的某个 Mobbin 屏幕**，点名并链接到其 `mobbin_url`。

每项主张都说明其证据有多强：两个或更多产品的屏幕展示了它，即为先例；一个即为示例；没有则是你自己的判断，判断只填补一个动作的部分，绝不填补整个动作。在报告中，每个条目下方的 References 行展示了这一点。在其他任何地方，句子会说明它：它点名产品，或它以“My opinion is to”开头。没有证据支撑的主张会被删除，而不是弱化。

在用户读到的任何文本中——从第一个范围界定选项到对“为什么”的回答——这排除了以下内容：

- **步骤 3 之前不谈 Mobbin。** 在搜索运行或收藏集被阅读、且查看过其图像之前，不引用任何东西，因此范围界定轮次只使用源和用户的原话。
- **不谈你未查看过的产品类别。** 不要“most apps”、“best-in-class”、“industry standard”或“the way high-converting paywalls do”：点名产品，每个都是你查看过的屏幕。
- **不要凭记忆的研究、原则或启发式。** 不要“research shows”、点名的定律或点名炫耀的权威，因为该技能没有研究语料库。
- **任务走查和 taste.md 是方法，不是记忆。** 缺陷的理由是它所阻碍的任务步骤，而 [references/taste.md](references/taste.md) 作出判断，但绝不在用户面前被点名。
- **不谈行为结果。** 绝不要说这次运行能转化、留存、建立信任或减少摩擦：问题点名它所阻碍的步骤，动作点名它所做出的决策，用户要求的指标保留其原话，绝不声称已被改变。
- **没有背后的东西就不下质量形容词。** “Dated”、“cluttered”、“modern”、“clean”或“premium”只出现在用户的原话中，或在其所描述的部分旁边。
- **以像素为单位测量，以所见之物说话。** 尺寸、坐标、十六进制值和比例留在你的笔记中；用户读到的是它们意味着什么（“the close button is now the platform's minimum size”）、屏幕上的数字、相对可见部件的位置，以及任何你未测量或计数的数字。
- **不谈图像未展示的主张。** 关于某个动作的句子只点名读者在图像比例下能在 BEFORE 和 AFTER 之间看到的差异，绝不点名计划了却未落实的东西。

## 输入

用户以他们拥有的任何形式带来目标：工作目录渲染出的代码库、一张图像、一个设计文件、一个在线页面，或某个已连接工具所暴露的内容。该形式即**源**。用环境所提供的任何手段读取它，然后一视同仁地对待每个源：一个区域、元素、可见状态、调色板、字体与间距尺度，以及它们所暗示的设计系统。形式只决定区域如何命名、状态从何而来，以及渲染以何种形式返回。

他们还可能带来自己的原话（一句抱怨、一个目标、一个约束、一种外观）和自己的参考（一张截图、一个 Mobbin 链接、一个产品名），它设定重设计的目标，同时 Mobbin 屏幕仍锁定在其旁，以免结果成为对单个产品的复制。Mobbin 通过 `search_screens`、`search_sections` 和 `search_flows` 提供参考；当它们未连接时，用一行说明并停止，因为该技能不靠记忆运行。

用户点名、链接或指向的**收藏集**（“我保存的屏幕”、“我的结账和付费墙收藏集”、“我从 Duolingo 保存的屏幕”）是他们选择的证据。它用 `list_collections` 和 `get_collection_contents` 代替搜索来读取，且除非用户另有说明，运行保持在其中，如 [references/collections.md](references/collections.md) 所述。

## 模式

两种模式，由调用中的 `--explore` 或 `--targeted` 设定，或当两者都未给出时作为第一个范围界定问题来询问（[references/scoping-round.md](references/scoping-round.md)）：

- **探索（Explore）**（`--explore`）：最多三个变体，每个都从单一方向整体构建，作为基线旁的模型图。在用户选定一个之前不应用任何东西。阅读 [references/variations.md](references/variations.md) 并遵循它；它说明了替换以下哪些步骤。
- **定向（Targeted）**（`--targeted`）：修复用户勾选的问题，在一个应用于源的设计中完成，按以下书面步骤执行。

## 输出

渲染以源进入时的形式返回：

| 源 | 渲染 |
|--------|--------|
| 一个代码库 | 对源的编辑 |
| 一个设计文件 | 在原始文件旁新建一个画框，使用设计工具自身的工具写入，以便基线得以保留 |
| 一个只能读取的设计文件 | 一张以产品自身调色板、字体和间距捕获的模型图，在范围界定时说明一次 |
| 一张图像 | 一个 PNG |
| 其他任何内容 | 三者中最接近的一种，在范围界定时说明 |

在承诺能写画框之前，先检查是否确实能写，因为大多数设计工具连接只能读取。在探索模式下，每个源首先都渲染为模型图，而该表适用于用户选定的变体。

当渲染可被捕获时，回复以前后对比图开头（步骤 7），然后是报告和结尾菜单（步骤 8）。参考看板和参考列表仅在要求时提供。

## 1. 界定目标

先阅读源，以便每个问题都点名本产品的真实部件。

用一行**写下任务**：谁到达、他们来做什么，以及完成是什么样子。“A team admin choosing a plan and paying for it, done when the payment is confirmed.” 它来自源和用户的原话，绝不来自参考。组件或区块在其屏幕任务的职责中说明其部件：筛选行的职责是缩小表格范围。当任务无法容纳于一行时，第一个问题就问它。

列出目标可展示的**状态**（加载、空、错误、禁用、溢出、窄视口），并标记每个状态是当前已展示、在源中但不可达，还是缺失。对于图像，除非用户另有说明，否则只有图片所示的状态存在。将列表保留在笔记中：仅当某个被勾选的问题需要时，才构建缺失的状态。

**走一遍路径**，以那个人从到达至完成，通过任务走查的六项检查。每一次中断都是一个候选问题。

1. **路径引导。** 目光落在任务的第一步，一个主要控件完成它，且没有偏离路径的东西与之竞争，包括区域外围的外壳已经做的事。
2. **每个决策的信息都在其旁**，而非隔一次滚动或点击。
3. **任务所需的东西没有缺失。**
4. **每个标签和值都是真实的。** 控件做它所说的事，而无标签的图标是平台或产品已经教会用户的（关闭、分享、返回、它重复的某个标签页）；设计系统全程使用的无标签图标是它的风格，不是缺陷。一个值出现两次时读法相同，总计与其各行相符。
5. **目标进入的每个状态**都让任务得以完成，或说明为何不能。
6. **平台的最低标准成立**：目标尺寸、最小字号档、来自系统自身配对的对比度。

写下每个候选，将其与所中断的步骤绑定，并陈述得能让渲染展示其已修复：“the seats stepper sits below the plan choice it prices, so the price is chosen blind”。“It looks dated”在点名它所拖慢的步骤之前不是候选。按每个候选阻碍路径的程度排序，用户自己的抱怨优先，用他们的原话。步骤 6 以同样方式走查渲染。

**然后询问**范围界定轮次，如 [references/scoping-round.md](references/scoping-round.md) 所述，并借助 [references/scope-and-preserve.md](references/scope-and-preserve.md) 处理意图、区域、共享组件和平台。每个答案和假设都写入 **Scope 行**。

## 2. 冻结基线

完整阅读目标及其使用的设计系统：token 或可见调色板、它由之构成的组件、主色、间距和字体尺度。

按此顺序写下**保留列表（Preserve list）**，即必须保留的内容：

1. **领域。** 产品保持为同一种产品；来自其他领域的参考只出借结构。
2. **设计系统与主题。** 结构在系统内变化，系统绝不换成参考的。
3. **文案与数据。** 屏幕保留自己的文字和数据。新标签用本产品的术语书写，绝不取自参考。
4. **目标之外的一切。** 当目标是单个组件或区块时，屏幕其余部分不变。边界的命名方式与源所示一致：代码中的文件和符号，图像中的可见边缘。
5. **用户要求保留的内容**，来自保留问题，以及目标中已经有效的任何部分（点名），在更改它的代价大于收益之处。

确定**问题列表**：勾选的问题，每个与所中断的步骤绑定，每个获得一个动作，**至多五个**，以便报告和图像保持可读。其他所有候选连同其步骤和所见之处进入**延后记录（Deferred record）**。该记录在步骤 3 和 6 增长，绝不出现于报告中，并用于结尾菜单，以便各轮之间所见之物不丢失。

## 3. 搜索并锁定参考

**来自收藏集。** 当用户指向他们保存的内容时，先阅读 [references/collections.md](references/collections.md)。它设定读取什么以及搜索是否可以加入。本步骤中其他一切仍然成立，只是以收藏集的屏幕代替搜索结果。

**探索问题空间。** 在第一次调用之前，调用 Mobbin 的 `search` 技能并在其规则下搜索。每个问题从一个查询开始，在第二次拉取之前至多两个，并查看每一张图像。只有当回答某问题的决策在屏幕中可见时，该屏幕才算数，而非在其标题中。按产品计数，而非按捕获计数：一个应用的二十张捕获只是一个先例，由最能展示该决策的那张捕获引用。优先匹配任务而非匹配外观，绝不混合意图；区块屏幕不为组件提供信息。

**识别方向。** 当相关屏幕在结构上分歧时（标签页对芯片行，会行动的卡片对会链接的卡片），按各自共享的结构性决策将它们分到不同的一侧。

**表明立场。** 为整个目标选定一侧，而非每个问题各选一侧；三方分歧归入能回答最多问题的一侧。写下它的应用、它们共享的决策，以及一句说明为何它契合任务的话，具体到它无法同时为另一侧辩护。整体采用该侧：它的控件、层级和尺度，以产品自身的组件和字体呈现，并按 [references/taste.md](references/taste.md) 所述构建。另一侧不产生动作，并在报告中获得一个从句。参考暴露而走查遗漏的中断，连同展示它的屏幕进入延后记录。

**标记所选一侧的参考**，每个都注明应用、`mobbin_url`、它做了而基线未做的事（取用项），以及你不会沿用的内容（舍弃项：浅色或深色背景、强调色、字体、文案、示例数据）：

- **锚点（Anchors）**：最能展示该方向的屏幕。重设计主要基于这些构建。通常两到四个；当搜索只找到一个时，一个也可。
- **池（Pool）**：同侧的其他屏幕。某个动作可以为一个细节（如空状态或一个标签）引用其中一个，且它不塑造其他任何东西。
- **丢弃（Dropped）**：不回答任何问题的屏幕，保留在你的笔记中并附一行理由，绝不使用。

## 4. 规划动作

一个**动作（move）**是对目标的一处更改，用所选一侧屏幕所展示的决策修复一个被勾选的问题。每个问题写下一条，**至多五个**，按各自解锁任务的程度排序。一个带来多个控件的控件模式仍是一个动作：上限限制每轮的问题数，绝不限制该侧被采用的程度。

每个动作列出其**点名清单（roll call）**：展示它所做出的确切决策的锚点和池屏幕，每个都附其 `mobbin_url`。

- **引用决策，而非元素。** 为徽标行添加标签的动作需要一个带标签徽标行的屏幕；光秃秃的徽标行不算数。
- **引用被移开之物落于何处。** 将某物推到一旁的动作需在某个被引用的屏幕上展示它去往何处，否则报告将把该放置称为你的判断。该侧屏幕所缺乏的包裹层、行或块会被移除，引用至这些屏幕，并予以报告。
- **无屏幕，无动作。** 判断只填补屏幕未展示的细节（放置、措辞），依 [references/taste.md](references/taste.md)，绝不填补整个动作。

删除或修正符合以下情况的动作：

- 为另一个动作已覆盖的问题添加第二处更改；
- 移除基线曾有的内容（一个方案、链接、行、操作、徽标、标签）：它留在屏幕上，放在某被引用屏幕所放之处，或在无屏幕展示时放在基线原有之处；
- 将内容移出此屏幕：它保留本轮，结尾菜单将该动作作为后续提供，并引用将其放到别处的屏幕；
- 做所选一侧没有产品做的事，或仅因基线有而保持旧形态；
- 在没有点名问题且同侧有两个产品如此做的情况下，添加一个现成细节（愿望清单爱心、评分行、徽标、悬停抬起、骨架屏、每个标签上的图标、额外微文案、渐变叠加）。

然后写**动作表（move table）**，每个动作一行：问题、侧、点名清单、它添加什么、它移除什么。没有列问题或点名清单的行，或破坏保留列表的行，被删除。不构成行的东西一律不构建。

## 5. 应用

按 Outputs 为源命名的形式构建动作表，仅更改目标：绝不更改主题、其 token 或共享组件，除非被要求。保留列表守住请求所说的任何内容，而在构建时这意味着：

- **仅从产品的设计系统构建。** 使用其现有组件、颜色 token、间距和字体尺度，让其主题处理深色模式。绝不添加一次性控件、原始颜色值，或新的库、字体或图标集。
- **采用参考的结构，而非其外观。** 绝不复制其浅色或深色背景、强调色、字体、徽标或插画风格。

被引用的屏幕决定每个动作做什么；[references/taste.md](references/taste.md) 决定它如何融入本产品。

保持交互真实：一个控件驱动真实状态，而非装饰。不要接上任何动作未要求的线路（分页、排序、新数据或派生值）。仅当某个动作使其新近可达且某被引用屏幕展示它时，才渲染该状态。

## 6. 对照任务检查渲染

在捕获之前，以任务所点名的那个人走查渲染，通过任务走查的六项检查，外加仅针对渲染的三项检查：

- 仅渲染某个动作使其可达的状态；
- 目标之外没有任何东西移动；
- 未破坏 [references/taste.md](references/taste.md) 中的任何致命缺陷。

只阅读渲染：不进行新搜索。

每项检查通过或失败。在目标和保留列表内修复失败项，然后再次运行每项检查，因为修复可能撤销某项通过。至多三轮。

- 需要新动作、新参考或目标之外内容的失败不予修复：删掉导致它的动作，并在其问题下报告。
- 第三轮之后仍存在的失败以同样方式删掉其动作。
- 没有动作导致的中断进入延后记录。

然后，在环境有检查命令之处，运行它并修复其报告的内容。重新阅读渲染以发现设计系统之外的任何东西：不是 token 的颜色、超出尺度的值、手工构建的主题、外来的组件或素材、新的依赖。每项都在报告中修复或点名。
