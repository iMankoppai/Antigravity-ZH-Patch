# AI 运维

使用 Harness AIDA 配置 AI 驱动的预测性故障分析和智能告警关联。

## 说明

### 步骤 1：确定范围

确认用户的 org、project、service 和可观测性技术栈。

```
Call MCP tool: harness_list
Parameters:
  resource_type: "project"
  org_id: "<organization>"
```

### 步骤 2：识别 AI 运维任务

确定用户需要哪个工作流：

1. **预测性故障分析**——在 SLO 突破之前基于 ML 检测即将发生的故障
2. **告警关联与降噪**——对相关告警分组并抑制重复项

### 步骤 3：配置预测性故障分析

从用户处收集：
- 服务名称和数据源（Datadog、Prometheus、CloudWatch）
- 预测范围（提前 30 分钟、1 小时、4 小时、24 小时）
- 训练数据期（30 天、90 天、6 个月）
- 模型类型偏好（异常检测、时间序列预测、集成）

配置故障预测场景：

1. **内存泄漏检测**——标记每个窗口内存增长超过阈值的服务
2. **磁盘耗尽**——预测填满时间并提前 N 小时告警
3. **连接池饱和**——当连接池使用率持续超过阈值时告警
4. **延迟退化**——在 SLO 突破之前检测逐渐变慢
5. **部署引发的回退**——将指标变化与近期部署关联

配置告警：
- 设置预测置信度阈值（低于阈值则抑制以减少噪声）
- 将告警路由到 PagerDuty、Slack 或其他渠道
- 使用 AIDA 启用自动生成的运行手册建议
- 建立误报反馈循环以改进模型

配置数据源：
- 指标源（Prometheus、Datadog、CloudWatch）
- 日志源（Elasticsearch、Splunk、CloudWatch Logs）
- 跟踪源（Jaeger、Datadog APM、AWS X-Ray）
- 模型再训练频率（每天、每周、每月、数据漂移时）

### 步骤 4：配置告警关联与降噪

从用户处收集：
- 当前告警量（告警/天）和目标减少百分比
- 正在使用的告警工具（PagerDuty、OpsGenie、Grafana、Datadog）
- 关联偏好

配置告警关联：
- 关联窗口：对 N 分钟内触发的告警分组
- 关联方法：基于拓扑、基于时间、基于 ML 或混合
- 用于基于拓扑关联的服务依赖映射

配置降噪：
- 去重：跨源合并相同告警
- 抑制：在维护窗口期间抑制已知噪声告警
- 聚合：将 N 个相似告警合并为单个事件
- 优先级评分：使用历史解决数据进行基于 ML 的严重性分配

配置智能路由：
- 路由到拥有受影响服务的团队
- 升级：若在 SLA 内未确认则自动升级
- 上下文增强：将近期部署、相关日志和运行手册链接附加到告警

## 示例

- “为我们的支付服务设置预测性故障分析”——配置 ML 模型以检测内存泄漏、磁盘耗尽和延迟退化
- “将我们的告警噪声减少 50%”——配置告警关联和去重以减少每日告警量
- “在磁盘用完前 4 小时提醒我们”——配置带提前预警的磁盘耗尽预测
- “关联我们微服务间的告警”——使用服务依赖映射设置基于拓扑的告警关联
- “为告警自动生成运行手册建议”——启用 AIDA 驱动的运行手册推荐

## 性能注意事项

- ML 模型需要 2-4 周基线数据，预测才会变得可靠——初期预期误报率较高。
- 基于拓扑的关联需要准确的服务依赖映射——过期的映射会导致漏掉关联。
- 告警关联窗口应平衡分组（更长 = 更少告警）与响应时间（更短 = 更快通知）。
- 再训练频率应与系统变化速度匹配——快速变化的服务需要每周再训练。

## 故障排查

### 高误报率
- 提高置信度阈值以抑制低置信度预测
- 提供误报反馈以改进模型
- 检查训练数据期是否包含有代表性的流量模式（工作日、周末、峰值）

### 预测未触发
- 核实数据源已连接并发送指标
- 检查预测范围是否适合该故障模式
- 确保模型已完成初始训练（至少 2-4 周）

### 告警关联漏掉相关告警
- 增大关联窗口以捕获级联故障
- 如果使用基于拓扑的关联，更新服务依赖映射
- 检查所有告警源是否都已集成（缺失的源会导致孤立告警）
