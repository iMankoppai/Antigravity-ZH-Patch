# Zoho Desk 跟进与 SLA 管理

不让任何事项溜走。产出经过排序、可执行的列表，而不是数据堆砌。

## 工作流

1. **定义范围**：谁的工单（用户、某个团队、某个部门）、哪些状态以及时间窗口。若未指定，默认使用用户的未结工单，并说明这一点。
2. **拉取候选工单**，并为每个工单获取：状态、优先级、负责人、到期日、SLA/首次响应/解决截止时间、最后一条客户消息、最后一次坐席操作、最后发送的跟进。
3. **将每个工单分类**到以下一个桶中（首个匹配生效）：
   - **已违约（Breached）**：到期日或 SLA 截止时间已过。
   - **有风险（At risk）**：截止时间在未来 4 个工作小时内，或在总 SLA 窗口的 20% 以内。
   - **等待客户（Awaiting customer）**：状态为 Waiting on Customer，或最后一条消息为外发。
   - **等待内部/第三方（Awaiting internal/third party）**：受阻于工程、审批、供应商。
   - **陈旧（Stale）**：超过团队阈值（默认 3 个工作日）无人有任何活动。
   - **正常（On track）**：当前无需任何操作。
4. **为每个工单推荐操作和时机**，使用下表。
5. **排序**：已违约 > 有风险 > 高优先级陈旧 > 等待内部 > 等待客户。

## 跟进节奏（默认值，按组织政策调整）

| 情形 | 操作 |
|---|---|
| 等待客户，已静默 2 个工作日 | 首次提醒（使用 `zoho-desk-customer-communication`） |
| 再静默 3 个工作日 | 第二次提醒，说明关闭日期 |
| 再静默 2 个工作日 | 建议以无响应为由关闭，并附确认 |
| 受阻于内部团队 2+ 天且无更新 | 催促负责人；若优先级高则升级 |
| 临近 SLA 且尚无首次响应 | 立即响应或重新分配 |

在推荐再次提醒之前，务必检查客户近期是否已回复，以及今天是否已发送过提醒。

## 输出格式

```
Scope: <who/what, window>   As of: <date/time and timezone>

Needs action now
1. #<id> <subject> - <bucket> - <why, with dates> -> <action> (by <when>)
...
Coming up
...
Waiting (no action yet): <count and ids>

Drafts or changes I can prepare (need your confirmation to send/apply): <list>
```

## 防护准则

- 区分测量值（时间戳、已配置的 SLA）与估计值（你的风险判断）。
- 在数据可用时，使用工作时间和组织的节假日日历；若你假设按日历时间计算，请说明。
- 批量提醒：先展示收件人列表和措辞；仅在明确确认后发送。切勿自动关闭工单。
