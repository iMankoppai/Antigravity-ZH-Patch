# SERP 分析

分析某个关键词当前的 Google 结果，并产出一份标注了证据来源的内容决策。回答三个问题：

1. 对这个关键词，哪种内容格式能胜出（指南、清单文、工具、产品页）？
2. 哪些 SERP 特性会吸走点击，无论你排第几？
3. 你能做到什么前 10 没做到的？

把格式集中度当作关于搜索意图的证据，而不是某种格式一定会排名的保证。

## 规则来源

使用这些标签来解读材料性规则：

- **Semrush 支持的指引：** 引用的 Semrush 文章中所陈述的方法论。保留其场景和注意事项。
- **MCP 契约要求：** 在当前官方 Semrush MCP 的发现和报告 schema 中已验证的行为或限制。
- **行业经验法则：** 一种站得住脚的分析实践，而不是 Semrush 指标或搜索引擎要求。
- **可配置默认值：** 用户可以更改的工作流或输出选择。

让 Semrush 数据、人工页面观察、用户提供的证据和模型判断清晰分开。绝不要把 Semrush 产品界面的示例变成公开 MCP 的能力。

## 开始之前

一次性询问这些输入。

- **目标关键词。** 每次分析一个。多关键词分析是另一个技能（见 `keyword-research`）。
- **国家/数据库。** 如果用户未指定，默认美国。不同地区的 SERP 差别巨大。
- **用户的域名。** 可选。只把它用于通过某份其 schema 接受目标的报告做当前排名或域名上下文研究。受测的关键词报告不接受域名，也不返回 Personal Keyword Difficulty（PKD）。
- **Semrush MCP 是否已连接。** 这会为实时 SERP 数据解锁 Semrush 关键词、自然搜索、SERP 和 URL/域名报告。如果未连接，分析回退为人工 SERP 检查。Semrush MCP 通过 Semrush 自己的认证流程连接，所以没有需要粘贴的 API 密钥。

## 如何使用 Semrush MCP

只使用 Semrush MCP。

MCP 对每份报告使用三步模式：

1. 调用发现工具（`keyword_research`、`organic_research` 或 `domain_overview`）查看可用的报告。
2. 对你需要的那份具体报告调用 `get_report_schema` 获取其必需参数。
3. 用这些参数调用 `execute_report` 拉取数据。

对本技能承担大部分工作的报告：

- `phrase_this`（通过 `keyword_research`）——只从搜索量、CPC、竞争密度、结果数、趋势、原始意图和通用 Keyword Difficulty 中请求所需字段。
- `phrase_organic`（通过 `keyword_research`）——位置、位置类型、域名、URL，以及返回的 SERP 特性代码。它不返回标题标签、字数、Authority Score、页面流量或引荐域名。
- `domain_rank`（通过 `domain_overview`）——可选的域名或 URL 聚合排名、关键词、流量、成本和 SERP 特性总计。它不返回 Authority Score。

每当契约可能已改变时都调用 `get_report_schema`。只使用该 schema 中存在的、且执行时被返回的字段。

如果没有可用的 Semrush MCP，就在目标国家进行人工 SERP 检查。不要把人工采集的 SERP 数据呈现为详尽无遗。

## MCP 访问与成本护栏

- 在第一次 `execute_report` 调用之前，告诉用户 Semrush MCP 查询会消耗 API 单位。把 `phrase_organic` 限制在分析所需的结果范围内，只请求所需的字段，只有在审阅第一批之后才扩展。默认绝不请求全部行。
- 如果认证不完整、某个必需的工具、报告、schema 或字段不可用，或执行因访问或单位问题失败，就停止该 MCP 分支。说明哪些内容不可用、哪些发现受影响，然后使用下面的最强回退。绝不猜测缺失的 SERP 或竞争对手指标。

## 回退阶梯

使用可用的最强数据源，并说明你用了哪一个。

1. Semrush MCP 关键词、SERP、自然搜索和 URL/域名报告。
2. 用户提供的 Semrush UI 导出。
3. 在目标国家与语言下的人工浏览器检查。
4. 用户提供的前 10 URL。把缺失的指标标注为未知，而不是猜测。

## 分析框架

按顺序运行这六个步骤。

1. 拉取关键词指标
2. 识别搜索意图
3. 编列 SERP 特性
4. 分析前 10 结果
5. 确定胜出的格式
6. 找出缺口

以一份可复用的 SERP 证据对象和一条简短的内容建议结束。`content-brief` 技能应当消费这份证据，而不是重新运行相同的报告。

---

## 1. 拉取关键词指标

用 `keyword_research` 发现 `phrase_this`，然后调用 `get_report_schema` 和 `execute_report`。请求决策所需的字段：

- **搜索量**，针对与用户地理区域匹配的数据库。
- **通用 Keyword Difficulty**，当作 Semrush 的比较性估算，而不是对用户域名的预测。
- **CPC 和竞争密度**，当作付费搜索的市场信号，而不是业务价值的证明。
- **趋势和原始意图**，在返回时记录。

保留实际值和报告名称。如果某个意图代码或趋势值无法从已验证的文档中解码，就保留原始值，并把解读标注为未解析。不要编造 PKD 或个性化排名潜力。

---

## 2. 识别搜索意图

如果尚未分类，使用 `keyword-research` 技能中的启发式链条。

- **从查询语言。** "如何"和"什么是"指向信息型。"最佳"和"对比"指向商业型。"购买"和"免费试用"指向交易型。
- **从 SERP 本身。** 在依赖单个意图标签之前，先审阅返回的结果集和当前渲染的 SERP。
- **从 SERP 特性。** 把特性当作支撑证据。购物结果可以支持交易型意图；精选摘要和 PAA 可以支持信息型意图；混合特性可以表明分裂的意图。

留意**分裂的意图**。有些 SERP 混合了格式。"最佳视频剪辑笔记本电脑"可能显示一个产品轮播（交易型）、三篇对比文章（商业型），和一段 YouTube 购买指南（商业-信息型）。当意图是分裂的，就在分析中点明。你将需要在一个页面里处理不止一种格式才能胜出。

---

## 3. 编列 SERP 特性

列出 `phrase_organic` 返回的、或通过当前人工 SERP 确认的每一项特性。当映射未经验证时，保留原始特性代码。

- **精选摘要。** 在可观察时记录其格式和当前来源。把点击影响当作依赖查询的。
- **AI Overview。** 自然结果上方的 AI 生成摘要。它能改变点击行为，所以记录它是否出现、以及它是否引用了用户或竞争对手。
- **People Also Ask（PAA，用户还问了）。** 把相关问题当作主题证据，而不是自动的大纲或 H2 清单。
- **知识面板。** 右侧的实体框。主要与品牌关键词相关。
- **图片包。** 图片轮播。表明视觉意图（食谱、示意图、产品）。
- **视频轮播。** 把它当作视频或混合格式需求的证据。
- **热门产品轮播。** 把它当作购物或交易型需求的证据。
- **本地包。** 把它当作本地意图的证据。
- **讨论与论坛。** 把它当作存在社区或第一人称视角的证据；不要推断 Google 为何选择它们。
- **富结果。** 记录可见的增强内容与符合条件的结果类型。不要承诺 CTR 提升。

对每一项目前存在的特性，记录两件事：

- 今天用户的哪些竞争对手（如果有）占据该特性。
- 什么证据支持去争取它、以及适用哪些平台要求。

只有当页面类型和可见内容能满足某特性时才推荐它。不要把一个特性普遍标注为容易或难以赢得。

---

## 4. 分析前 10 结果

运行 `phrase_organic` 并设 `positions_type: organic` 和能覆盖所请求自然结果集的最小上限。只用 `positions_type: all` 作为一次单独的 SERP 特性发现遍；特性位置行不是额外的自然搜索排名。只把返回的字段作为 Semrush 数据记录：

- **位置和位置类型。** 保留原始值。
- **域名和 URL。** 保留有排名的 URL，而不只是根域名。
- **触发的和域名级的 SERP 特性代码。** 只从已验证的文档解码。

保留原始行，但在计数页面格式、竞争对手或头部结果集时对相同的排名 URL 去重。如果同一个 URL 出现在多个自然搜索位置，记录那些位置，并把页面级分析中把它当作一个页面。绝不要让重复的特性行虚增竞争对手或观察的数量。

只通过单独的证据来源添加以下内容：

- **人工页面证据：** 标题标签、可见页面格式、日期、具名专家、原创数据、工具、模板、示例，以及有用时可直接测量的字数。
- **额外的 Semrush 报告：** 只有当合适的已发现报告确实为所请求目标返回该字段时，才使用聚合流量、关键词、反向链接或 Authority Score 证据。
- **模型判断：** 格式分类、内容角度、缺失信息和机会评估。

不要把页面流量、引荐域名、字数、Authority Score 或标题标签归于 `phrase_organic`。不要从固定数量的域名、URL、链接或访问量推断主题权威性或排名可达性。

---

## 5. 确定胜出的格式

对每个观察到的结果分类，然后报告实际的分布。把集中度描述为高、混合或不确定，并展示用于该判断的计数。不要强加固定的普遍截断值。

标记异常值，并解释它们为意图图景增添了些什么。不要仅凭一个排名结果就推断某发布者的主题权威性。

让格式匹配意图：

- 信息型：指南或文章。
- 商业对比型：清单文、对比表或汇总。
- 交易型：产品或定价页面。
- 对话或故障排查型：一个直接回答、社区视角、支持资源，或观察到的 SERP 所支持的另一种格式。

---

## 6. 找出缺口

缺口是关于用户如何更好地满足所观察意图的一个模型辅助假设。缺口并不保证排名提升。

四个常见的缺口类别。

- **原创数据。** 一项调查、一项内部研究、一个基准。前 10 互相引用彼此的数据。新数据立刻脱颖而出。
- **具体范围。** 前 10 都是泛泛的。你的是针对一个行业、一个用例、一个人设。
- **更契合的格式。** 观察到的结果留下了一个用户需求，可用工具、计算器、模板、清单、视频或其他合适的体验来满足。
- **时效性和准确性。** 前 10 引用的是过时事实。你的是当前事实。前 10 在某件专家会抓到的事情上是错的。你的是对的。

如果这些缺口中的任何一个都无法实现，就在输出中点明。有些 SERP 已经饱和。诚实的选择有时是"别写这个，写一个相邻的、缺口真实存在的东西。"

---

## 如何报告发现

输出一个单一的、包含以下章节的证据包。

### 关键词快照

陈述可用的搜索量、通用 KD、意图、CPC、竞争密度和趋势。包含数据库、报告和不可用的字段。

### SERP 特性

分别列出返回的与人工观察到的特性。对每一项，陈述证据、当前占据者（可见时）、适用要求和置信度。

### 前 10 表

| 位置/类型            | URL           | 返回的特性     | 观察到的格式  | 页面证据         | 额外的 Semrush 证据               | 缺口假设              | 证据状态           |
| ------------------- | ------------- | --------------------- | ---------------- | --------------------- | ----------------------------------------- | --------------------------- | ------------------------- |
| [原始位置/类型] | [排名 URL] | [原始 + 解码代码] | [模型判断] | [人工观察] | [报告和实际值，或不可用] | [清晰标注的推断] | [完整/部分/人工] |

### 建议策略

推荐最有充分支持的格式、角度和相关 SERP 特性。陈述置信度，并点明会改变该建议的证据。

### 可复用的 SERP 证据对象

返回一个紧凑的结构化块，包含：

- 关键词、数据库、采集日期和数据来源；
- 可用的关键词指标和原始意图；
- 有排名的 URL 及其原始位置和特性代码；
- 人工观察到的格式和页面证据；
- 格式分布和分裂意图评估；
- 缺口假设、局限和置信度。

当用户继续进入简报创建时，把这个对象传给 `content-brief`。

关于报告本身的三条规则。

- 陈述实际值及其证据来源。绝不用模型估算来填充指标列。
- 为你标记的每个模式点明一个具体的竞争对手 URL。"Competitor.com/foo 用一个 3 行表格占据了精选摘要"是可执行的。
- 如果证据暗示契合度差或竞争异常强，解释证据并推荐一个相邻目标。不要宣告某个 SERP 客观上是无法赢的。
