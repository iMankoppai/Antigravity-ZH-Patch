# 内容简报

本技能把一个目标关键词转化为一份内容简报，供写作者用来交付一篇可发布成稿的文章。它对于一份简报里该有什么、不该有什么有明确主张。一份好的简报设定范围、框定角度，然后让开。

简报不应替你写文章。过度规定的简报读起来像合规检查清单，产出的内容排名也像合规检查清单。任务是给写作者足够的上下文去做出真正的决定，而不是给出足够的规范去消除这些决定。

## 开始之前

一次性询问这些输入。

- **目标关键词。** 每份简报一个主关键词。如果用户给了一个列表，与用户一起选择，或按相关性、业务价值、意图契合度、可获得性和 SERP 证据来排优先级。不要默认选搜索量最高的词。
- **域名。** 可选，但能通过揭示相关的既有页面、排名和内链目的地来改善结果。不要声称受测的公开 MCP 会为所提供域名返回个性化关键词难度。
- **Semrush MCP 是否已连接。** 这会为实时 SERP 数据解锁 Semrush 关键词和自然搜索报告。如果未连接，你仍然可以编写简报，但 SERP 分析应标注为人工或方向性的。Semrush MCP 通过 Semrush 自己的认证流程连接，所以没有需要粘贴的 API 密钥。
- **目标受众。** 一份没有受众定义的简报会产出对谁说话的内容。一次性询问用户是否有书面 ICP（理想客户画像）、内容指引或受众笔记。如果没有，请他们就读者是谁写两句话。
- **目标。** 为流量排名、支持一个既有活动、构建一个主题中心、刷新一个表现不佳的页面。目标会改变简报。

## 如何使用 Semrush MCP

只使用 Semrush MCP。

可调用的 MCP 工具名称是研究入口加上 schema 执行。报告/产品名称（如 Keyword Overview 和 Keyword Magic Tool）是通过 schema 流程选择的，而不是作为工具直接调用。

- 使用 `keyword_research` → `phrase_this` 获取可用的通用关键词指标，如搜索量、通用 KD、意图和 CPC。受测 schema 没有域名输入、PKD 字段或 SERP 特性字段。
- 使用 `keyword_research` → `phrase_related` 和 `phrase_questions` 获取相关词和问句式关键词。这些报告提供关键词行，而不是 Keyword Magic Tool 分组、自动聚类或大纲。
- 使用 `keyword_research` → `phrase_organic` 并设 `positions_type: organic` 获取排名 URL。只有当有意需要特性位置行时才用 `positions_type: all`，并把这些行与自然搜索排名分开。保留每一个原始行，但为页面审查和格式计数目的对相同 URL 去重，同时记录每一个返回的位置。不要把字数、页面流量、页面级引荐域名或 Authority Score 归于该报告。

保守地解读报告输出：

- 完全按返回的样子保留数字型的意图和 SERP 特性代码。只有当当前已发现的 schema 或官方文档提供了该映射时，才把代码映射为人类可读的标签。否则，把原始代码显示为未解析，并把任何人工的意图或特性归类单独保留为模型推断或观察。
- 在简报中使用前，筛查相关词和问题行是否有重复、显式搜索操作符、损坏编码、明显拼写错误和跑题词。保留原始行，说明筛查规则和排除计数，绝不把被移除行的指标赋给纠正后的拼写。
- 当两份 Semrush 报告不一致时，保留两个值，并附上各自的报告名称、数据库、目标和可用的日期或快照上下文。不要悄悄合并它们，也不要选更有利的那个值。解释（如果有）使用哪个值来做决定以及为什么；否则把该指标标记为不一致。

标准工作流保持不变：通过 Semrush MCP 的 `keyword_research` 或 `organic_research` 发现 → 针对具体报告 `get_report_schema` → 带参数 `execute_report`。

如果提供了结构化的 SERP Analysis 工件，就消费它的关键词上下文、意图、特性映射、排名 URL、证据可用性、格式分布、缺口和置信度，而不是重新运行相同的研究。否则，用上述报告构建那份证据，只在需要时获取额外的域名或 URL 证据。把人工检查、格式分类、缺口检测、聚类和大纲决策标注为分析师/模型判断，而不是 Semrush 返回的字段。

## MCP 访问与成本护栏

- 在第一次 `execute_report` 调用之前，告诉用户 Semrush MCP 查询会消耗 API 单位。只请求所需的字段，使用能回答该问题的最小结果上限，只有在审阅第一批之后才扩展。默认绝不请求全部行。
- 如果认证不完整、某个必需的工具、报告、schema 或字段不可用，或执行因访问或单位问题失败，就停止该 MCP 分支。说明哪些内容不可用、简报的哪些部分受影响，然后使用下面的最强回退。绝不编造或悄悄替换缺失的 Semrush 指标。

## 回退阶梯

使用可用的最强数据源，并说明你用了哪一个。

1. Semrush MCP 关键词、SERP 和 URL/域名报告。
2. 用户提供的 Semrush UI 导出。
3. 在目标国家进行人工 SERP 检查。
4. 用户提供的竞争对手 URL 和第一方受众笔记。把缺失的指标标注为未知，而不是猜测。

## 证据契约

把来源出处与置信度分开。对材料性输入和建议使用这些标签：

- **Semrush 数据：** 由某个具名 MCP 报告返回的值。包含报告名称。
- **Semrush 支持的指引：** 有链接的 Semrush 来源支持的编辑性建议。不要把它呈现为搜索引擎的要求。
- **用户提供：** 第一方目标、受众知识、转化证据、约束，或已批准的来源。
- **人工观察：** 直接检查到的、而 MCP 未返回的 SERP 或页面特征。
- **模型推断：** 从现有证据推导出的建议，比如格式、角度、分组或大纲结构。
- **可配置默认值：** 出于可用性而非普遍 SEO 规则而选择的起始范围。

在面向用户的简报中，在来源会影响某条断言应如何被信任之时展示出处。把标签保持紧凑，放在证据或理由说明中，而不是给每句话都打标签。另外把置信度评为高、中、低，并在缺失证据降低置信度时说明缺失了什么。

## 简报结构

一份可用的简报有这八个部分。其他一切都是可选的。

1. 目标关键词与意图
2. 受众与角度
3. SERP 语境（前 10 分析）
4. 标题与元描述
5. 大纲（H1、H2、H3）
6. 范围指引
7. 链接计划（内部与外部）
8. 风格与语调说明

按顺序运行它们。每一部分为下一部分提供输入。

---

## 1. 目标关键词与意图

记录主关键词和可用的 `phrase_this` 指标，如搜索量、通用 KD、CPC 和原始意图值。把不可用的字段标记为未知，并让每个值都与其 Semrush 报告绑定。不要把 SERP 特性归于 `phrase_this`。简报以关键词开头，好让写作者在读其他任何内容之前就理解拟定的搜索目标。

只有当返回的代码有经核实的映射、或实时 SERP 证据支持一个单独的模型判断时，才把意图归类为信息型、导航型、商业型或交易型。标注所用的路径。写作者应产出的格式随意图而变化。

- 信息型意图常常支持一篇指南或文章，但要对照实时 SERP 确认格式。
- 商业型意图常常支持对比、替代方案、评测或定价语境。
- 交易型意图常指向一个产品、分类、服务或定价页面。推荐恰当的页面类型，而不是自动停止工作流。
- 导航型意图常指向一个产品或品牌页面。混合或分裂的意图是可能的，所以在决定前先用观察到的 SERP 分布。

只添加同一个页面能够满足、且不混入不相容意图的次要关键词。从 Semrush 行加上透明的意图和 SERP 重叠分析中选择它们；不要承诺该页面会对所包含的每一个词都排名。

## 2. 受众与角度

两个简短的段落。不要更多。

受众段落点明读者是谁、他们对该主题已经知道什么、他们需要从文章中获得什么。"B2B SaaS 的资深 SEO，已经读过三篇关于此的指南，想要别人都没覆盖的那部分"是有用的。"营销人员"则不是。

角度段落点明页面的钩子。这篇文章说了什么前 10 没有说的？如果你不能用一句话回答，简报就没准备好。对该主题的泛泛覆盖会输给现有的前 10，因为它们已经覆盖了该主题。

可能的角度：

- 一个第一方数据点（一项调查、一个实验、一个写作者可引用的工具结果）。
- 一个反主流的解读（常规建议在这里是错的，而我们能证明）。
- 一个更具体的范围（前 10 都是泛泛的，我们的是针对某个特定行业或用例）。
- 一个更有用的格式（前 10 是成堵的文字，我们的是工具、计算器、模板或清单）。

## 3. SERP 语境

通过 Semrush MCP 或直接检查 SERP，拉取该主关键词的前 10 自然结果。

对一组有代表性的排名结果，记录：

- URL
- 页面类型（指南、清单文、对比、计算器、产品页）
- 只有当能直接测量时才记录字数；标注为描述性的竞争对手证据，而不是目标或排名因素
- 显著的角度或差异化之处
- 该页面是否是其站点上某个主题中心的一部分

当能通过已映射的 `phrase_organic` 代码或直接 SERP 检查核实出现哪些 SERP 特性时，也记录下来：精选摘要、PAA 框、视频轮播、购物结果和 AI Overview。绝不从未映射的数字代码去猜特性名称。使用已核实的特性来识别合适的格式和可能的搜索者需求。不要假定固定的答案长度，也不要声称 AI Overview 总是减少点击；只描述观察到的证据所支持的内容。

给写作者标记的常见模式。

- 如果一种格式占主导，记录该模式的强度，以及某种替代格式是否能更好地满足相同意图。
- 如果排名页面显示出一致的深度或范围，把它当作描述性上下文，同时定义读者所需的覆盖。不要把竞争对手的字数转化为排名要求。
- 如果某个站点占据多个结果，把这种集中作为一个观察记录下来。不要仅凭这一点就证明该站点拥有该主题。

## 4. 标题与元描述

两个标题候选，一个元描述。

标题：

- **Semrush 支持的指引：** 目标为 550 像素或更少，通常 50 到 60 个字符，以降低截断或改写的风险。搜索引擎和 AI 系统并不强制一个最大值，所以用一个预览来检查，而不是把这个范围当作硬性失败。
- 让每个标题都具描述性、简洁，并与页面的实际主题和意图一致。
- 在它准确传达主题时，自然地把主关键词包含一次。不要堆砌相关变体。
- 只有当页面真正兑现时，才添加一个价值信号，如受众、范围、证据或格式。
- 提出不同的、经得起辩护的角度供用户选择。让标题和 H1 足够相似，以传达相同的页面主题，而不必要求完全一致。

元描述：

- **Semrush 支持的指引：** 目标为不超过 135 个字符，以降低跨设备截断的风险。把它当作一个编辑目标，而不是排名因素或硬性校验失败。
- 准确概括页面，给搜索者一个有用的访问理由。
- 当它能提升相关性和清晰度时，自然地包含主关键词或一个接近的变体。
- 针对观察到的搜索意图，并在一个简洁回答有用时考虑回答核心问题。
- 预览结果，因为设备宽度、字符宽度、查询加粗和搜索引擎改写都会影响显示的摘要。

不要仅仅为了制造点击而扣留一个有用的答案。标题和描述必须如实代表页面实际交付的内容，不带误导或标题党式框架。

## 5. 大纲

大纲是简报的脊梁。把这一点做好，其余的就交给写作者。

从三个来源构建大纲。

- SERP 分析。识别反复出现的主题和有意义的缺口，然后基于受众和意图决定哪些属于本页面。不要自动照搬竞争对手的标题。
- People Also Ask（用户还问了）。把相关问题当作研究输入；只有当它们有助于满足页面目的时才纳入，而不是作为自动的 H2 或常见问题条目。
- Semrush 关键词行。通过透明的意图和 SERP 重叠分析对相关词分组，然后把所得的主题当作大纲证据。不要暗示 MCP 会返回语义聚类，也不要暗示固定数量的词会映射到一个标题。

推荐一个清晰的 H1，描述页面、针对其主要意图，并与标题的主题保持一致。**Semrush 支持的指引：** 从为一个主标题设一个 H1 开始，然后用 H2 作为主要章节、H3 作为子章节。把一个 H1 当作编辑和结构上的建议，而不是排名保证或自动失败条件。

让标题清晰、直接、具描述性。在实际可行时目标为少于 60 个字符，但不要为了达到目标而牺牲清晰度。像"定价"这样简洁的标签当它毫不含糊地描述该章节时是有效的。让每个标题聚焦于一个主题或想法。

在 H1 中包含主关键词，在 H2 和 H3 中在自然契合时包含相关的次要关键词或问题。把读者放在首位；不要强行使用完全匹配的措辞。用 H1 和第一个 H2 来针对主要意图，然后用后面的标题来处理相关的辅助意图。

把 H3 当作直接隶属于某个 H2 的真正子章节，而不是仅仅为了制造视觉节奏。保持层级合乎逻辑且一致。

**可配置默认值：** 给每个大纲条目 1 到 3 行说明，涵盖该章节应处理什么、要引用的任何具体来源、以及要包含的任何数据点。避免起草该章节本身。写作者需要结构，而不是散文。

## 6. 范围指引

定义页面必须覆盖的问题、证据、示例和决策，以满足受众和意图。竞争对手的长度在直接测量时可以作为描述性的 SERP 语境报告，但绝不把它变成最小值、最大值、排名保证或填充公式。

如果写作者请求一个规划范围，把它做成一个明确标注的编辑性估算，基于已批准的大纲和预期深度。解释有用的完整性比匹配竞争对手的字数更重要。

## 7. 链接计划

内部链接。

- 在写作者开始之前识别相关的目的地。通过 Semrush 自然搜索报告、用户提供的导出，或手动网站地图，从用户现有的站点中拉取。
- 两个方向都要规划：从新页面到上下文相关的既有页面的链接，以及从相关的既有或权威页面到新页面的链接。
- **Semrush 支持的指引：** 目标为每篇新内容至少两到三条指向它的入站内部链接。把它当作一个编辑目标，而不是自动失败条件。基于上下文相关性来推荐出站内部链接，而不是一个固定数量。
- 当它们反映站点的实际架构时，使用支柱到聚簇和聚簇到支柱的链接。不要自动要求一个首页或支柱链接。
- 使用简洁、具描述性的锚文本——理想情况下五个词或更少。相关的内部完全匹配锚文本是可以接受的，但要避免关键词堆砌和像"点这里"或"本页"这样的通用锚文本。

外部链接。

- 识别所需的、相关的、可信且专业的外部来源，以佐证断言或提供有用的上下文。
- **可配置的来源质量默认值：** 在可用时优先采用政府来源、原创研究、一手产品文档和可信的行业出版物。不要把每个聚合站都自动视为不可接受；评估实际的来源和证据。
- 不要强加一个固定的外部链接数量。使用简洁、具描述性的锚文本，并且只有当链接为读者增加价值时才推荐它。
- 避免标题党、低质量信息、低质量目录或书签站点，以及任何旨在操纵排名的链接方案。
- 指向可信来源的常规编辑性链接不需要特殊的关系属性。当归站不应当被背书或关联时，使用 `rel="nofollow"`。用 `rel="sponsored"` 或 `rel="nofollow"` 标记赞助或联盟链接；不要一刀切地禁止它们。

## 8. 风格与语调说明

三到五个要点。涵盖：

- 阅读水平（技术性、主流、初学者）。
- 第一人称、第二人称，或不用人称。选一个并告诉写作者。
- 示例政策。真实数字和真实名称，还是假设性占位。
- 用户此前标记过的禁用短语或 AI 痕迹。
- 内部风格链接（一份语调文档、一个风格指南 URL）。

## 如何报告简报

把简报作为一份单一的 markdown 文档输出。使用与上述八个章节匹配的 H2 章节标题。在底部包含一个"给写作者的说明"章节，用于一切不适合结构化章节的内容。

关于简报本身的两条规则。

- 陈述实际值及其来源。"Semrush `phrase_this`：搜索量 2,400，KD 38%，意图代码 1（映射未解析）"在没有已验证映射时是有用的。"不错的标的"则不是。
- 为你引用的每一个数据点建议具体的来源。一份说"根据最近的一项研究"却不点名该研究的简报，是在要求写作者产生幻觉。
- 标注人工观察和模型生成的建议，并在不完整的证据实质影响拟定的格式、角度或大纲时，添加一个简短的置信度说明。

让简报与主题的复杂度和写作者的需求成比例。删除那些不改变写作者决策的说明。
