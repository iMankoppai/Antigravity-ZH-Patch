# 竞争对手缺口分析

把某个域名与相关的搜索竞争对手进行比较，并把证据转化为用户可以采取的行动。把这些竞争对手类型区分清楚：

- **搜索竞争对手：** 争夺相同自然查询的域名。
- **直接业务竞争对手：** 向相同客户群提供相似产品或服务的公司。
- **间接业务竞争对手：** 以不同或替代性的供给服务相似受众或需求的公司。
- **品牌竞争对手：** 用户可能想以其为基准进行对标的成熟品牌。

不要假定这四个群体是相同的。当出版商、市场平台、社交网络和用户生成内容站点反复满足相同的查询时，它们可以是正当的搜索竞争对手。标注它们的类型和相关性，而不是自动排除它们。

## 规则来源

使用这些标签来解读材料性规则：

- **Semrush 支持的指引：** 引用的 Semrush 文章中所陈述的方法论。保留其场景和注意事项。
- **MCP 契约要求：** 通过官方文档或实时 schema 发现所确认的限制、字段、操作或访问条件。
- **行业经验法则：** 能帮助排定证据优先级的分析师判断，但不是官方 Semrush 规则。
- **可配置默认值：** 用户可以更改的工作流或输出选择。

把规则来源与证据来源分开。在每一份输出中，都要把 Semrush 估算、第一方数据、提供的导出、人工观察和模型判断清晰区分开。

## 输入

只收集用户尚未提供的内容：

- 用户的域名。
- 任何已知的业务竞争对手。
- 市场和区域数据库。**可配置默认值：** 只有当用户没有给出地理背景时才使用美国。
- 目标：关键词发现、内容规划、反向链接机会、渠道对标，或完整对比。

根据用户的目标，只运行必要的模块。**可配置默认值：** 完整对比使用全部五个模块。

## 官方 Semrush MCP 工作流

对每个 MCP 分支，遵循 发现工具 → `get_report_schema` → `execute_report`。从发现和 schema 结果中复制当前的报告名称与参数，而不是依赖记忆。

使用以下已验证的路由：

| 模块             | 发现工具         | 报告                                | 用途                                                                                                 |
| ------------------ | ---------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 搜索竞争对手 | `competitors_research` | `domain_organic_organic`              | 自然竞争对手、相关性、共享关键词和流量估算                                  |
| 关键词缺口        | `competitors_research` | `domain_domains`                      | 跨越最多五个域名的共享、缺失、未开发及偏弱的关键词证据                    |
| 内容缺口        | `organic_research`     | `resource_organic_unique`             | 自然搜索表现最好的页面、关键词数、流量和流量份额                                           |
| 页面充实    | `organic_research`     | `resource_organic`                    | 某个入围域名、子目录或 URL 的关键词和排名                                       |
| 反向链接缺口       | `competitors_research` | `backlinks_matrix`                    | 在多个目标之间共享的引荐域名                                                        |
| 反向链接细节    | `backlinks_research`   | `backlinks_refdomains`                | 单个目标的 Authority Score、反向链接计数和首次/最近出现证据                           |
| 反向链接上下文   | `backlinks_research`   | `backlinks`                           | 某个入围引荐域名的来源页、目标页、锚文本、响应码和链接属性 |
| 流量对比 | `traffic_overview`     | `summary` 以及需要时的 `sources` | 跨域名的流量和渠道估算                                                              |
| 付费搜索        | `paid_search_research` | `resource_adwords`                    | 付费关键词、位置、CPC 和流量估算                                                    |

在第一次 `execute_report` 调用之前，告诉用户 Semrush MCP 查询会消耗 API 单位。**可配置默认值：** 从决策所需的字段和一个 30–50 行的上限开始。只有在第一批结果集不足时才扩展或分页。

`traffic_overview` 需要相应的 Trends 订阅。如果访问不可用，使用用户提供的 Semrush Trends 导出，或把流量对比标记为不可用。不要用自然搜索估算来替代总流量或渠道数据。

如果认证、访问、单位、某份报告或某个必需字段不可用，就停止该分支并说明缺少什么。绝不编造替代指标。

## 回退

**可配置默认值：** 按以下顺序使用可用的最强来源并加以标注。在可用时，优先采用更具权威性的用户提供的第一方证据。

1. 官方 Semrush MCP 报告。
2. 用户提供的 Semrush 导出。
3. 用户已连接的 Google Search Console 数据或导出（针对其自有站点），加上对竞争对手的人工 SERP 检查。
4. 用户提供的竞争对手 URL 或反向链接导出。

在最终输出中，让 Semrush 估算、第一方数据、人工观察到的事实和模型判断保持可区分。

## 数据质量保障

把返回的行作为来源证据保存，并构建一份单独的分析后的入围名单。绝不悄悄改写查询、URL、域名、指标或报告值。

- 在推荐关键词行之前，筛查其中是否有显式搜索操作符（如 `inurl:`）、损坏的编码、重复项、明显的拼写错误和跑题的查询。只有当一行与用户的目标无关时才排除它；记录筛查规则和排除计数。不要把一个被移除行的指标转移到纠正后的拼写上。
- 在把竞争对手页面当作内容机会之前，先检查其 URL、主题、页面类型，以及与用户受众的关系。把自动生成、跑题、不安全或不符合品牌调性的页面排除在行动清单之外，同时记录它们已从分析中排除。
- 如果在报告 schema 中发现的有效字段或操作在执行时被拒绝，不要继续重试，也不要声称服务端过滤器已生效。请求最小的有用结果集，并在可能时执行等价的、透明的客户端过滤；否则把该分支标记为不完整。
- 把原始报告行与模型辅助的相关性、聚类、安全性和优先级判断分开保存。

## 模块 1：发现并选择搜索竞争对手

**Semrush 支持的指引：** 从共享排名中识别自然竞争对手，然后把它们与用户的直接、间接和品牌竞争对手进行比较，而不是仅凭直觉。

为用户的域名运行 `competitors_research` → `domain_organic_organic`。审查竞争对手相关性、共享关键词数，以及自然流量估算。

把结果与用户已知的竞争对手比较，并标记：

- 自然搜索重叠很少的业务竞争对手。
- 用户没有点名的搜索竞争对手。
- 在目标市场中重叠异常强的域名。

当用户有偏好时，让他们自己选择竞争对手。否则，选择能回答该问题的最小相关对比集。**可配置默认值：** 从三个开始以便分析可控，当额外的域名代表一个有意义的不同竞争对手或会改变结论时扩展到四个。

用共享查询、目标受众、市场、搜索意图和页面类型来评估候选相关性。不要要求一个自称的竞争对手必须出现在任意的前 10 名单中。如果一个业务竞争对手的搜索重叠有限，解释这种区别，而不是悄悄移除它。

## 模块 2：找出关键词缺口

运行 `competitors_research` → `domain_domains`。**MCP 契约要求：** 该报告总计支持最多五个域名，因此在一次请求中比较用户域名与不超过四个竞争对手。

使用当前 schema 操作构建所请求的集合：

- **在所有选定的竞争对手中都缺失：** 先把竞争对手域名用交集（`*`）符号列出，再把用户域名用差集（`-`）符号放在最后。
- **在任一选定的竞争对手中未开发：** 从一个使用交集（`*`）的竞争对手开始，用并集（`+`）加入其他竞争对手，再用差集（`-`）减去用户域名。
- **共享：** 对每个所比较的域名都使用交集（`*`）。
- **偏弱：** 检索共享关键词并比较返回的位置列；只有当用户有排名、且选定的竞争对手排名更高时，才把某个关键词标为偏弱。

"缺失"始终指该次请求中包含的所有竞争对手。不要硬编码为"全部三个"。保留域名顺序，使每个位置列保持可归属。

只使用服务于用户目标的过滤器。可用的报告证据包括位置、搜索量、CPC、竞争密度、趋势和通用的 Keyword Difficulty（关键词难度）。受测的公开 MCP 不为该报告返回 Personal Keyword Difficulty（个性化关键词难度）。

当服务端显示过滤器尽管出现在了已发现的 `domain_domains` schema 中却失败时，只检索最小的有用行集，并在上述数据质量保障下于客户端筛查。说明清洗是在检索之后应用的，并保留原始值。

**Semrush 支持的指引：** 对于一个不太知名或尚未建立多少权威的站点，可以把 KD 0–49 作为一个起步预设提供。保留该场景，并说明该范围是可调整的。不要从 Authority Score 推断出一个不同的截断值。把搜索量范围当作可选的用户过滤器，而不是价值的定义。综合考量相关性、意图、业务价值、可获得性和第一方需求。

按决策需要返回尽可能多的相关行。不要承诺一个预定数量的机会。按共享意图和 SERP 重叠对入围的关键词进行聚类，并把聚类标注为模型辅助的分析，而不是本报告返回的字段。

## 模块 3：找出内容缺口

为每个选定的竞争对手和用户的域名运行 `organic_research` → `resource_organic_unique`。**可配置默认值：** 从按流量排序的一个小集合开始，并比较：

- 竞争对手有强页面而用户没有相关页面的主题。
- 双方都有页面，但用户页面表现不佳的主题。
- 竞争对手展现出更广主题覆盖的领域。

不要假定前 20 个页面或某个固定的建议数量总是合适的。只有当最初的页面不能代表竞争对手的相关内容时才扩展。

对于入围的页面，在需要关键词级充实信息时，用 `resource_organic` 并配上确切的 URL。把页面格式和主题深度分类保留为人工或模型判断。

在推荐某个竞争对手页面之前，应用数据质量保障。一个高流量或高排名的自动生成、跑题或不符合品牌调性的 URL，是关于原始报告的证据，而并不自动是一个有用的内容缺口。

用观察到的页面和主题证据来描述覆盖深度。不要用固定的"五个竞争对手页面对一个用户页面"规则来宣告某个聚类缺口。

## 模块 4：找出反向链接缺口

以用户和选定的竞争对手为目标运行 `competitors_research` → `backlinks_matrix`。保留目标顺序，并在过滤之前把每个返回的反向链接桶映射到其域名。

对于真正的缺口，要求用户的反向链接桶等于零、且至少有一个选定的竞争对手桶大于零。如果当前的执行契约只可靠地支持相等过滤器，就用 `equals 0` 过滤用户桶，然后要么从每个竞争对手桶中排除 `equals 0` 以得到全竞争对手交集，要么在客户端选择任一竞争对手桶大于零的行。不要仅凭匹配计数就推断缺口，也不要依赖 `greater_than` 操作，除非当前 schema 和一次小型执行测试都接受它。

当某个入围域名需要单目标的聚合细节（如 Authority Score、反向链接计数或首次/最近出现日期）时，使用 `backlinks_research` → `backlinks_refdomains`。在把某一行称为直接潜在客户之前，在当前 schema 支持时，用 `backlinks_research` → `backlinks` 并配以引荐域名过滤器，检查至少一个被链接的竞争对手。检查返回的来源 URL、来源标题、目标 URL、锚文本、响应码和链接属性。一个缺乏相关编辑上下文的 matrix 行只是一个候选，而不是一条外联建议。

**受 Semrush 方法论启发的行业经验法则：** 用以下方面评估潜在客户：

- 主题和受众相关性。
- 竞争对手被链接时所处的页面和编辑上下文。
- 来源正当且活跃的证据。
- 用户是否有一个值得同样链接的资产。
- Authority Score 作为一个质量信号，而不是自动的通过/不通过阈值。

不要要求 Authority Score 30+、12 个月的新鲜度窗口，或链接到固定数量的竞争对手。让证据和细分领域来决定一个潜在客户是否值得去做。

把输出分成：

- **直接潜在客户：** 用户的资产可以被可信地加入的相关页面或域名。
- **关系模式：** 值得理解的反复出现的作者、出版商、记者或社区。

## 模块 5：比较流量与渠道策略

**Semrush 支持的指引：** 比较竞争对手用来触达相同受众的渠道，但只衡量与用户决策相关的渠道。

运行 `traffic_overview` → `summary`，以获取最多五个域名的并排流量和渠道估算。只有当某个渠道需要详细的来源分析时才使用 `sources`。

使用 `paid_search_research` → `resource_adwords` 获取 Semrush 付费搜索估算。人工搜索观察可以补充报告，但必须标注为轶事性的、且依赖地点/时间。

对于新闻通讯、社交账号、社区、播客或视频渠道，在可能时检查第一方页面。不要把搜索摘要、粉丝数或订阅者声明呈现为 Semrush MCP 数据。

点明重要的渠道差异，但不要假定用户应当照搬竞争对手的每一个渠道。

## 共享的优先级排序层

**可配置的优先级排序框架：** 汇总所选模块的发现，并用以下方面排序：

- **相关性：** 与用户的受众、市场、目标和搜索意图的契合度。
- **证据强度：** 直接第一方证据、Semrush 数据、人工观察，或模型推断。
- **可行性：** 内容、技术、关系和运营方面的要求。
- **预期价值：** Semrush 流量或流量价值估算、第一方转化证据，以及战略价值。

不要承诺固定的见效时间范围。不要把 Semrush 估算的流量或流量价值描述为收入。只有当用户提供了转化率以及客户或交易价值时，才估算收入，并展示计算过程和假设。

## 输出

**可配置的输出默认值：** 返回一份按优先级排序的行动清单，随后是为所用模块准备的简明证据表。

| 优先级 | 缺口类型        | 证据                                                                                         | 竞争对手参照 | 建议操作                                                            | 可行性 | 预期价值                         | 置信度 |
| -------- | --------------- | ------------------------------------------------------------------------------------------------ | -------------------- | ----------------------------------------------------------------------------- | ----------- | -------------------------------------- | ---------- |
| 1        | 内容更新 | 竞争对手页面在共享聚类上有排名，而用户现有页面位置偏弱 | 确切的竞争对手 URL | 围绕所展示的意图和缺失证据刷新现有页面 | 中      | 标注为 Semrush 估算的机会 | 高       |

对于每条建议：

- 点明支持它的竞争对手域名、URL、引荐域名或渠道资产。
- 报告实际返回的值，并在可用时附上其来源和日期或数据库。
- 把表现不佳的现有资产与真正缺失的资产区分开。
- 标记不可用的字段，而不是悄悄估算它们。
- 把模型推断的聚类、页面类型、相关性和优先级解释为判断。
- 总结重要的噪音、安全和相关性过滤器，包括排除了多少行以及为什么。
