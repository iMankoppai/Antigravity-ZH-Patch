# 反向链接审计

审计某个域名的反向链接档案，并产出一份标注了证据来源的行动计划。回答四个问题：

1. 当前的反向链接档案实际包含什么？
2. 哪些链接或模式值得人工审查？
3. 哪些竞争对手的引荐域名是看似可行的机会？
4. 哪些被链接的目标页面可能需要恢复、更新或重定向？

不要仅凭一个指标就称某个反向链接有害、有损或安全。不要仅凭一个自动化模式就建议使用 disavow（拒绝链接）。

## 规则来源

- **Semrush 支持的指引：** 综合评估相关性、权威性、放置位置、锚文本上下文、引荐域名多样性、链接属性、历史模式和竞争对手重叠度。风险决策需要人工审查。
- **MCP 契约要求：** 公开的 MCP 暴露 Backlink Analytics（反向链接分析）报告。在受测契约中，它不暴露 Backlink Audit Toxicity Score（反向链接审计毒性评分）、有害标记、清退名单或 disavow 工作流。
- **行业经验法则：** 风险标签、机会层级和推广优先级是分析师的判断，除非用户采用明确的标准。
- **用户可配置的默认值：** 竞争对手数量、行数上限、日期窗口和权重必须契合该站点的市场与用途。没有任何 Authority Score（权威评分）或链接数量截断值是普遍有效的。

## 输入

一次性询问：

- 要审计的根域名或确切 URL；
- 竞争对手，如果用户想要缺口分析；否则提出单独识别搜索竞争对手；
- 已知的建链、赞助、联盟、迁移或负面 SEO 历史；
- Google Search Console 是否对不自然链接显示了人工处置（manual action）；
- 用户的优先页面和市场。

使用产品认可的连接器或用户提供的 Search Console 证据。如果用户没有核实过 Manual Actions（人工处置），把该状态标注为**未确认**。不要索取 Semrush API 密钥；官方 MCP 使用 Semrush 认证。

## 官方 Semrush MCP 工作流

先发现报告族、获取 schema，然后只执行受支持的报告。

### 来自 `backlinks_research` 的档案类报告

- `backlinks_overview`：在要求时返回聚合的 Authority Score、反向链接数、引荐域名、引荐 IP、已索引 URL，以及 follow/nofollow/sponsored/UGC 计数。
- `backlinks_refdomains`：引荐域名、在被明确要求时的域名 Authority Score、反向链接数、首次/最近出现时间、IP 和国家。
- `backlinks_anchors`：锚文本、引荐域名数、反向链接数，以及首次/最近出现时间。
- `backlinks`：来源 URL 和目标 URL、锚文本、日期，以及受支持的链接标志。用它做行级排查，但在未审查来源页面的情况下，不要把它当作编辑性收录的证明。
- `backlinks_historical`：逐月的反向链接和引荐域名趋势。
- `backlinks_pages`：目标页面及其响应码、反向链接数、引荐域名数，以及最近出现时间。使用返回字段的准确含义；该报告本身并不证明当前的引荐流量或转化。

### 来自 `competitors_research` 的对比类报告

- `backlinks_comparison`：每个所提供目标一行聚合数据。
- `backlinks_matrix`：跨越所提供目标的引荐域名与反向链接计数。要找出缺口，把所分析域名的桶过滤为零，并保留至少有一个竞争对手计数大于零的行。

`targets` 和 `target_types` 是并行数组，长度必须相等且顺序相同。绝不要把 `backlinks_matrix` 描述成一个独立的 Backlink Gap 产品报告，也不要添加 schema 未返回的产品 UI 字段。

## 访问与证据护栏

- 告诉用户 Semrush 调用可能消耗 API 单位。先用一个有代表性的样本起步，当要求彻底覆盖时再分页。
- 在需要时明确请求 `authority_score` 或 `domain_authority_score`。只有在该确切字段被返回时，才使用 **Authority Score** 这一标签。
- 把 Semrush 指标、用户提供的证据、人工页面检查和模型判断分开。
- Authority Score 是 Semrush 的一个比较性指标，不是 Google 的评分，也不证明某个链接好或坏。
- follow/nofollow 构成、国家、IP、首次出现日期和锚文本都是上下文——而不是独立的判风险结论。
- 受测的公开 MCP 不返回 Toxicity Score（毒性评分）。如果用户提供了 Backlink Audit 导出，把其中的毒性字段标注为仍需人工审查的产品数据。
- 如果某份报告为空或未通过校验，说明哪些内容不可用。不要悄悄替换成别的指标，也不要编造风险评估。

## 回退阶梯

1. 官方 Semrush MCP Backlink Analytics 报告。
2. 用户提供的 Semrush Backlinks 或 Backlink Audit 导出。
3. Google Search Console 的 Links 导出，用于用户自有的抽样数据。
4. 其他用户提供的反向链接数据。

除非存在竞争对手的反向链接数据，否则竞争对手缺口不可用。Search Console 的 Links 报告是一个样本，绝不能描述为完整的反向链接索引。

## 工作流

### 1. 建立档案快照

运行 `backlinks_overview` 并记录：

- 目标和目标类型；
- 在被要求且被返回时的 Authority Score；
- 反向链接数和引荐域名数；
- 在被返回时的引荐 IP 和已索引 URL；
- 在被返回时的 follow、nofollow、sponsored 和 UGC 计数；
- 数据来源和检索日期。

当提供了竞争对手时，使用 `backlinks_comparison`。比较规模和构成，但不要声称引荐域名更多的域名会排名更高。

### 2. 审查引荐域名与链接

运行 `backlinks_refdomains`，然后在上下文重要时用 `backlinks` 检查选定的行。评估：

- 主题和受众相关性；
- 编辑标准与真实用户价值；
- 来源页面的上下文与放置位置；
- 链接属性；
- 跨域名、IP、日期、锚文本和目标页面的模式；
- 付费链接是否被恰当地标明。

不要仅凭低 Authority Score、共用 IP 或时间点就推断是 PBN（私有博客网络）。不要把来自单个域名的重复链接称为毫无价值；识别可能的全站放置并审查来源页面。

### 3. 审查锚文本

运行 `backlinks_anchors`。在有帮助时透明地对锚文本分类——比如品牌词、复合词、完全匹配、部分匹配、相关词、裸 URL、通用词、图片/空、页面标题——但除非报告提供，否则把这种归类标注为模型或分析师的推断。

结合上下文调查异常的集中现象。任何锚文本类别都没有普遍健康的百分比，完全匹配的文本也不是操纵的证明。要考虑目标页面、引荐域名、放置位置、获取历史，以及该模式是否是被有意制造的。

### 4. 在不编造毒性数据的前提下审查风险

用 Backlink Analytics 来浮现审查候选，而不是作出毒性裁决。寻找这样的组合：

- 付费的 follow 链接或大规模交换；
- 自动化、编辑控制力低的放置；
- 看起来为链接操纵而被控制的网络；
- 大规模的不相关或误导性锚文本；
- 无法解释的历史尖峰；
- 没有适当标注的合同、小部件、联盟或赞助链接。

对每个候选，陈述检索到的证据以及仍需人工审查的内容。语言或国家不匹配对一个国际业务来说可能是正常的。

### 5. 应用 disavow 安全闸门

Google 说 disavow 工具是一项高级功能，使用不当会损害表现。只有在以下两个条件都成立时才建议考虑它：

1. 存在相当数量的垃圾、人造或低质量链接；并且
2. 这些链接导致了人工处置，或很可能导致。

首先考虑对站点所有者创建或控制的链接进行移除或恰当标注。除非用户在审查证据后明确要求这一独立的高风险操作，否则不要生成或上传 disavow 文件。不要承诺恢复时间表。

### 6. 找出竞争对手的引荐域名缺口

运行 `backlinks_matrix`，用户域名在前，后接有效的竞争对手，且 `target_types` 相匹配。过滤出对用户目标为零链接、对竞争对手有一条或更多链接的行。

对每个返回的引荐域名：

- 保留各目标的计数，以及（仅在被返回时）Authority Score；
- 在称其为机会之前，先检查竞争对手的真实来源页面；
- 评估相关性、编辑契合度、链接上下文，以及用户的资产是否真的合适；
- 区分编辑性外联、合作/赞助的可能性、断链替换，以及"不合适"。

不要应用一刀切的 Authority Score、新鲜度或竞争对手数量截断。matrix 的一行证明的是反向链接的重叠，而不是具体的链接页面、可联系性或赢得链接的可能性。

### 7. 审查被链接的目标页面

运行 `backlinks_pages` 以识别目标页面和返回的响应码。非 200 的响应或过时的目标值得调查，但在规定重定向之前先核实实时 URL 和替代关系。

从以下选项中选择：

- 恢复或更新原始资源；
- 永久重定向到一个真正等价的页面；
- 联系链接站点更新目的地；
- 当响应或替代无法核实之时，保持该 URL 不变。

不要说重定向能回收固定比例的价值，也不要仅按 Authority Score 或引荐域名阈值来排优先级。

## 输出

从证据覆盖情况开始：

| 证据类别 | 来源/报告 | 范围 | 可用字段 | 局限 |
| -------------- | ------------- | ----- | ---------------- | ----------- |

然后呈现：

### 档案对比

| 目标 | Authority Score | 反向链接 | 引荐域名 | Follow | Nofollow | 证据日期 |
| ------ | --------------: | --------: | ----------------: | -----: | -------: | ------------- |

### 审查候选

| 优先级 | 引荐域名/来源 | 目标 | 检索到的证据 | 人工发现 | 建议操作 | 置信度 |
| -------- | ----------------------- | ------ | ------------------ | -------------- | ------------------ | ---------- |

### 竞争对手机会

| 引荐域名 | 用户链接 | 竞争对手链接 | 检索到的 AS | 来源页契合度 | 机会类型 | 置信度 |
| ---------------- | ---------: | ---------------: | -----------: | --------------- | ---------------- | ---------- |

### 被链接目标页面回收

| 目标 URL | 响应码 | 反向链接 | 引荐域名 | 已核实的替代 | 操作 | 置信度 |
| ---------- | ------------: | --------: | ----------------: | -------------------- | ------ | ---------- |

以以下内容结尾：

1. **立即行动：** 已确认的问题，责任明确、歧义低。
2. **人工审查：** 需要验证来源页面或获取历史的候选。
3. **接下来建设：** 可信的竞争对手或回收机会。
4. **不要行动：** 没有佐证证据的自动化或孤立信号。
5. **不可用：** Toxicity Score、人工处置状态，或其他实际未提供的数据。
