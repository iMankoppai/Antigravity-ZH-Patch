# 关键词研究

本技能针对一个主题或域名运行一套真实的关键词研究流程，按一位在岗 SEO 会着手的顺序进行。每一步都有清晰的输入、清晰的输出，以及在合适之处的一次 Semrush MCP 调用。

这套工作流有意偏向能驱动转化的关键词，而不是在截图里看起来很庞大的关键词。一个能成交的、搜索量 50 的词，胜过一个人人不买、搜索量 50,000 的词。

## 开始之前

一次性询问这些输入。不要跳过这一步。你为一个 10 页的 SaaS 站点所做的研究，不是你为一个 50,000 款商品的电商店铺所做的研究。

- **主题或种子关键词。** 用户实际想为什么排名？"SEO 工具"是一个主题。"给独立创业者的最佳 SEO 工具"更接近一个真实的查询。
- **域名。** 可选。当所选报告接受域名时，用它做既有排名研究、竞争对手对比和业务上下文检查。受测的公开 Semrush MCP 关键词报告返回通用 Keyword Difficulty（KD），而不是个性化关键词难度（PKD）。
- **Semrush MCP 是否已连接。** 这会为实时搜索量、难度、意图、CPC 和 SERP 特性数据解锁 Semrush 关键词报告。如果未连接，你仍然可以分类意图，但指标应标注为未知，而不是猜测。Semrush MCP 通过 Semrush 自己的认证流程连接，所以没有需要粘贴的 API 密钥。
- **用户是否有可用的 Google Search Console 数据。** GSC 揭示已经在获得曝光和点击的查询与页面。用它来识别相对于站点自身表现的机会，而不是强加一个普遍的位置、曝光或点击阈值。如果 GSC 不可用，请用户提供导出，或继续使用 Semrush 索引数据并披露该局限。
- **目标。** 品牌认知、线索获取、直接销售，或 AI 搜索可见性。目标决定了哪些关键词重要、以及如何排优先级。

## 如何使用 Semrush MCP

当已连接时，优先使用 MCP 而不是手动头脑风暴。只使用 Semrush MCP。标准工作流：

1. 调用相关的发现工具，列出 MCP 当前暴露的报告。
2. 为发现所返回的确切报告标识符调用 `get_report_schema`。
3. 用 schema 中的参数调用 `execute_report`。

与本工作流相关的 MCP 发现工具是 `keyword_research`、`organic_research` 和 `competitors_research`。在发现之后使用 `get_report_schema` 和 `execute_report`。不要把 Semrush 产品 UI 的名称替换成公开 MCP 的报告标识符。

- 使用 `keyword_research` → `phrase_this` 获取单个关键词的搜索量、CPC、竞争度、意图、趋势和通用 KD。其受测 schema 没有域名输入，也没有 PKD 字段。
- 使用 `keyword_research` → `phrase_related` 和 `phrase_questions` 做扩展。这些报告返回关键词行和指标，而不是 Keyword Magic Tool 的分组、子分组或自动聚类。
- 使用 `keyword_research` → `phrase_organic` 并设 `positions_type: organic` 获取有排名的自然搜索 URL。只有当有意需要特性位置行时才用 `positions_type: all`；把这些行与自然搜索排名分开，不要把重复的特性/自然搜索 URL 当作不同的竞争对手来计数。除非当前已发现的 schema 或官方文档提供映射，否则不要赋予人类可读的特性名称。
- 使用 `competitors_research` → `domain_domains` 做 Keyword Gap 对比。受测报告直接接受域名，不需要 Semrush 项目。
- 使用 `organic_research` → `resource_organic` 获取某个既有域名或 URL 有排名的关键词和页面。执行前核实其 schema。

遗留的 SEO API 风格关键词报告可能以数字代码而非标签返回意图。只解码有文档记录的值：`0` = 商业型，`1` = 信息型，`2` = 导航型，`3` = 交易型。把像 `1,0` 这样逗号分隔的值当作混合意图，把原始值保留在证据层，绝不猜测不熟悉或缺失的代码。

## 报告解读与数据质量

把这些规则应用于每一个候选来源，包括种子指标、相关词、问题、既有排名、Keyword Gap 行、提供的导出和 GSC 数据：

- 把原始报告行与分析后的入围名单分开保存。规范大小写和空白并去除完全重复项，但绝不在证据层改写查询、URL、代码或指标。
- 筛查显式搜索操作符、损坏的编码、畸形词元、明显的拼写错误，以及与用户主题、受众、市场或目标无关的词。当清洗实质改变了集合时，记录筛查规则和排除计数。不要把一个被移除行的指标转移到纠正后的拼写上。
- 完全按返回的样子保留数字型 SERP 特性代码。只有当当前已发现的 schema 或官方文档提供了其含义时才翻译代码；否则标注为未解析。把任何人工的特性分类单独保留为人工观察或模型判断。
- 在受测契约中，把 `position_type: -1` 的 `phrase_organic` 行当作传统的自然搜索位置。保留每一个原始行，但为页面审查和竞争对手计数目的对相同 URL 去重，同时记录每一个返回的位置。当 `positions_type: all` 返回额外的特性位置行时，不要把这些行混入自然搜索前 10，也不要重复计数同一个 URL。
- 当两份报告不一致时，保留两个值，并附上报告名称、数据库、目标和可用的日期或快照上下文。不要悄悄合并它们，也不要选更有利的那个值。解释（如果有）哪个值支持决策以及为什么；否则把该指标标记为不一致。
- 如果执行拒绝了某个在已发现 schema 中看似有效的字段或操作，不要继续重试，也不要声称服务端过滤器已运行。请求最小的有用未过滤结果集，并在可能时应用等价的透明客户端过滤；否则把该分支标记为不完整。

## MCP 访问与成本护栏

- 在第一次 `execute_report` 调用之前，告诉用户 Semrush MCP 查询会消耗 API 单位。只请求所需的字段，使用能回答该问题的最小结果上限，只有在审阅第一批之后才扩展。默认绝不请求全部行。
- 如果认证不完整、某个必需的工具、报告、schema 或字段不可用，或执行因访问或单位问题失败，就停止该 MCP 分支。说明哪些内容不可用、哪些发现受影响，然后使用下面的最强回退。绝不猜测缺失的关键词指标。

## 回退阶梯

使用可用的最强数据源，并说明你用了哪一个。

1. Semrush MCP 关键词和自然搜索报告。
2. 用户提供的 Semrush UI 导出。
3. Google Search Console 的查询和页面。
4. 人工 SERP 检查和第一方客户语言。把指标标注为未知，而不是猜测。

## 研究框架

按顺序运行这六个步骤。清单按优先级排序，因此步骤 1 的发现比步骤 5 的发现更重要。

1. 审计既有排名
2. 从种子词拉取关键词创意
3. 分类搜索意图
4. 按要紧的指标过滤
5. 按主题和意图聚类
6. 按业务价值排优先级

以一份按优先级排序的关键词计划结束。每个聚类都应有且只有一个主关键词，以及仅由共享意图和 SERP 重叠所支持的那些变体；没有普遍的聚类大小。

## 1. 审计既有排名

这里最强的信号是站点已经为其显现的东西。Google 第 2 页的页面常常能靠轻量工作就到达第 1 页，这是最便宜的流量。

如果 GSC 可用，拉取 Performance 报告，并就一个与其流量水平和决策周期相匹配的近期日期范围达成一致。找出有显著曝光但点击或 CTR 相对偏弱的查询或页面，以及排名接近站点能切实改善的结果区间的项。让过滤器可配置，并在输出中说明它们。

Semrush 把位置 11+、搜索量至少 100，以及 KD 0–49 作为一个可调整的既有排名示例。只把那个作为面向较不成熟站点的一个具名起步预设提供，绝不要作为 GSC 机会的定义。

对每个候选关键词，记录当前位置、曝光量，以及当前有排名的页面。这些是温暖的线索。

如果 Semrush MCP 可用，用 `phrase_this` 或通过 `keyword_research` 发现的当前批量关键词报告，来检索通用 KD 和其他所请求的指标。不要声称公开 MCP 有个性化难度，或接受所提供的域名来做关键词级个性化。

没有 GSC 时，对用户域名使用 Semrush Organic Research，从 Semrush 的索引中看到相似的排名数据。注意这是索引数据，不是直接的 Google 数据，且可能落后于 GSC。

## 2. 从种子词拉取关键词创意

从一个真实的种子词开始。糟糕的种子词产生糟糕的创意。选一个客户实际会输入的词，而不是营销友好的版本。"Email validation"是一个真实的种子。"Email deliverability optimisation platform"则不是。

用 `keyword_research` 发现 `phrase_related` 和 `phrase_questions`，然后让每份所需报告走一遍 `get_report_schema` 和 `execute_report`。它们可能返回：

- 相关词
- 问题（谁、什么、哪里、何时、为什么、如何等变体）。这些是长尾的金矿。
- 可用的指标，如搜索量、通用 KD、意图、CPC、趋势和相关性，取决于实时 schema。

从 MCP 推荐的探索性上限每份报告 30–50 行开始。只有当第一批没有覆盖相关的意图、修饰词、问题或竞争对手缺口时才扩展。合适的采集规模取决于站点的范围、目标和可用的 API 单位。

在聚类之前应用上面的共享质量控制规则。不要仅仅因为某个关键词搜索量低或为零就丢弃它。把每一次排除都当作模型辅助的判断，而不是 Semrush 数据。

几个过滤器能减少噪音。

- **只看问题。** 问句形式的关键词驱动 AI Overview 引用和 PAA 出现。它们往往搜索量较低但点击价值较高。
- **用户可控的难度。** 对于一个较新或权威性较弱的站点，可以把 KD 0–49 作为一个 Semrush 支持的起步预设提供。根据站点的权威性、主题相关性和目标调整它。
- **用户可控的搜索量。** 可以把搜索量至少 100 纳入同一个可选预设，但当第一方证据显示出需求时，低搜索量或零搜索量的词仍然可能重要。不要强加一个普遍的上限。

## 3. 分类搜索意图

搜索意图是你能读取的最重要的关键词指标。它决定了写什么内容、用什么格式，以及该关键词是否有可能转化。

四个类别。给每个候选打上一个（当重叠真实时打上两个）标签。

- **信息型。** 用户想学习。像"怎么做"、"什么是"、"为什么……"、"……指南"这样的短语。内容类型是文章、指南或视频。转化是间接的（认知或漏斗顶部）。
- **导航型。** 用户想要某个特定的品牌或产品。像品牌名、"登录"、"定价页"这样的短语。内容类型是实际的产品页面。如果用户已经是客户，转化是直接的。
- **商业型。** 用户在比较各种选项。像"最佳"、"对比"、"评测"、"……的替代方案"这样的短语。内容类型是对比、清单文或汇总。如果内容很好地定位了用户的产品，转化是高的。
- **交易型。** 用户已准备好购买或注册。像"购买"、"下载"、"折扣码"、"免费试用"这样的短语。内容类型是产品或定价页面。转化是直接且即时的。

读意图的三种方式。

- **从查询语言。** "如何修复索引错误"是信息型的。"最佳索引工具"是商业型的。"购买 SEO 软件"是交易型的。
- **从 SERP 特性。** 顶部的精选摘要通常意味着信息型。购物轮播意味着交易型。前 5 里的产品对比站点意味着商业型。
- **从词序。** "狗粮的配料"（有人在家自制）不同于"狗粮配料"（有人在店里读标签）。

如果 Semrush MCP 返回了意图标签，把它作为一个起点来信任，但通过查看实际的前 3 个 SERP 结果来核实。工具在模糊查询上会错误分类意图。

留意这些常见的误读。

- 当 SERP 显示混合意图（一些信息型结果、一些商业型结果）时，把关键词当作单一意图。发生这种情况时，两种意图都有效。胜出的页面通常是同时处理两者的那个。
- 为一个商业型关键词写一篇"如何做"指南。用户想要的是对比，不是教程。
- 忽视意图层次。"如何开始一个蔬菜园"需要土壤准备、季节性和病虫害防治，才能完全服务搜索者。

## 4. 按要紧的指标过滤

六个指标。把它们放在一起读，而不是一个一个读。

### 搜索量

一个关键词每月被搜索次数，平均而言。由 Semrush 为所查询的数据库报告。

相对于市场、转化价值、站点规模和第一方需求来解读搜索量。不要仅凭搜索量就把一个低搜索量的词视为可跳过、或把一个高搜索量的词视为无法企及。

一个要留意的陷阱。全球 vs 特定国家搜索量。Semrush MCP 默认使用你指定的数据库。一个美国站点看"tax filing software"得到的数字与一个英国站点差别很大。

### 关键词难度（KD）

Semrush 对一个关键词排名难度的通用估算，在受测的公开 MCP 中按 0 到 100 打分。

把 KD 当作比较性证据，而不是对某个具体站点是否会排名的承诺。把它与主题相关性、当前排名、SERP 竞争对手、内容质量、链接和业务价值一同考虑。不要把通用 KD 重新标注为 PKD，也不要创造普遍的可达性区间。

### 每次点击成本（CPC）

该关键词的平均付费出价。一个商业价值信号，不是排名信号。

CPC 能表明付费搜索竞争和商业兴趣，但高或低的值依赖行业。不要用固定的美元截断作为业务价值的证明。用用户的产品、利润率、转化和客户语言来验证价值。

### 搜索趋势

12 个月的搜索量轨迹。上升趋势暗示新兴机会。下降趋势暗示主题已过巅峰。

把方向、稳定性和季节性当作上下文。上升趋势可能表明一个新兴机会，而下降可能改变优先级，但没有任何固定百分比能决定决策。

留意季节性。"黑色星期五优惠"如果你在二月查看，看起来像是在下降。

### 搜索意图

已在步骤 3 分类。把该分类延续到过滤中。

### SERP 特性

该关键词的 SERP 上出现的东西：精选摘要、PAA 框、购物轮播、AI Overview、本地包。

SERP 特性重要有两个原因。

- 有些特性会吸走点击。如果 AI Overview 完整地回答了查询，即使在位置 1 自然搜索 CTR 也很低。除非该关键词是漏斗底部，否则降低其优先级。
- 有些特性创造机会。精选摘要和 PAA 结果会奖励清晰的标题、简洁直接的回答，以及适合该问题的格式。不要强加固定的答案长度。

## 5. 按主题和意图聚类

孤立的一个关键词很少是一个目标。只把同一个页面能满足、且不混入不相容意图的相关关键词分组。聚类大小应追随证据，而不是一个固定数量。

按以下两条规则聚类。

- 把同时共享主题和意图的关键词分组。"什么是反向链接"和"反向链接如何运作"是同一个聚类。"什么是反向链接"和"最佳反向链接工具"则不是。意图不同。
- 根据意图契合度、业务价值、需求和可获得性为每个聚类挑选一个主关键词——而不是仅凭搜索量。其余的关键词是该页面应自然覆盖的支撑变体。

受测的公开 MCP 不会从 `phrase_related` 或 `phrase_questions` 返回自动聚类。以透明的方式把聚类作为一个模型辅助或人工步骤，使用共享意图，并在有理由时使用 `phrase_organic` 返回的排名 URL 之间的重叠。把聚类归属标注为推断，而不是 Semrush 返回的数据。

两个常见错误。

- 在一个聚类里混入意图。该页面无法既服务好"如何写元描述"（信息型），又服务好"元描述生成器"（交易型）。
- 蚕食。同一站点上两个页面针对同一个聚类，会互相竞争。选一个页面并合并。

## 6. 按业务价值排优先级

按聚类位于漏斗何处、以及它们能带来多少收入来排序。

当用户的直接目标是收入时，使用这个 Semrush 支持的营收优先预设：

1. **漏斗底部（交易型、商业对比型）。** "最佳 [你的类别] 工具"、"[你的产品] 替代方案"、"[你的产品] vs [竞争对手]"。搜索量最低但最接近收入。
2. **漏斗中部（商业调查型）。** "如何选择 [你的类别]"、"[你的产品解决的问题]"。教育与筛选。
3. **漏斗顶部（信息型）。** "什么是 [你的类别]"、"[你的主题] 指南"。随时间建立权威但转化缓慢。

当用户的主要目标是品牌认知、类别教育、留存或其他结果时，不要强加这个顺序。根据所述目标调整排序，同时覆盖与该策略相关的漏斗阶段。

在每个层级内，次级排序依据是：

- 转化潜力（这个用户是否有向我们购买的意图？）
- 点击潜力（SERP 是否被吸走点击的特性所主导？）
- 现实世界需求（这个词是否出现在销售电话、支持工单或 Reddit 帖子中？）
- 可获得性（结合站点权威性、相关性和 SERP 竞争来解读的通用 KD）
- 趋势（上升 > 稳定 > 下降）

| 1        | [目标或阶段] | [聚类名称] | [主关键词] | [Semrush 值] | [Semrush 值] | [Semrush 或已核实的意图] | [支撑变体] | [GSC/第一方信号 + 清晰标注的模型判断] | [创建、刷新、合并或监控] |

关于报告本身的三条规则。

- 陈述实际值及其来源。"Semrush 搜索量 [值]，通用 KD [值]"是有用的。"不错的搜索量，可做的难度"则不是。
- 当返回意图代码时，显示解码后的标签，同时在证据中保留原始 Semrush 代码。把混合代码标注为混合意图，并对未知值不解码。
- 为每个聚类建议一个具体的下一步（写页面、刷新既有页面、建链）。用户应当知道该做什么，而不只是该知道什么。
- 标注假设和推断。如果意图、聚类、业务价值或可获得性是模型或人工判断，就说明这一点。
