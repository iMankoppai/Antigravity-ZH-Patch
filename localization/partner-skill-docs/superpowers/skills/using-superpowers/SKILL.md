## 规则

**在做出任何回应或行动之前，先调用相关或被要求的技能** —— 包括澄清性问题、探索代码库或查看文件。如果事后发现它不适用于当前情况，你不必使用它。

**进入计划模式之前：** 如果你还没有进行头脑风暴，请先调用头脑风暴技能。

然后宣布“使用 [skill] 来完成 [purpose]”，并严格遵循该技能。如果它有检查清单，为每一项创建一个待办。

## 技能优先级

当多项技能都适用时，流程类技能优先 —— 它们确定方法，然后由实现类技能（frontend-design 等）来完成。头脑风暴和系统化调试是 Superpowers 最常用的流程类技能，但此规则对任何这类技能都成立。

- “我们来构建 X” → 先 superpowers:brainstorming，然后是实现类技能。
- “修复这个 bug” → 先 superpowers:systematic-debugging，然后是领域技能。

## 危险信号

出现以下想法意味着停下——你在自我辩解：

| 想法 | 实际情况 |
|---------|---------|
| “这只是一个简单的问题” | 问题就是任务。检查是否有适用技能。 |
| “我需要先了解更多上下文” | 技能检查在澄清性问题之前。 |
| “让我先探索代码库” | 技能会告诉你怎么探索。先检查。 |
| “我可以快速查看 git/文件” | 文件缺少对话上下文。检查是否有适用技能。 |
| “让我先收集信息” | 技能会告诉你怎么收集信息。 |
| “这不需要正式技能” | 如果有技能存在，就使用它。 |
| “我记得这个技能” | 技能会演进。阅读当前版本。 |
| “这不算任务” | 行动 = 任务。检查是否有适用技能。 |
| “这个技能小题大做” | 简单的事会变复杂。使用它。 |
| “我先只做这一件事” | 在做任何事之前先检查。 |
| “这感觉很有效率” | 缺乏纪律的行动浪费时间。技能可以防止这一点。 |
| “我知道那是什么意思” | 知道概念 ≠ 使用技能。调用它。 |
