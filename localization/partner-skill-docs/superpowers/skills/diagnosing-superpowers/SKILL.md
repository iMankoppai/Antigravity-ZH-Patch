# 诊断 Superpowers

## 概述

与你的人类伙伴一起确定某次会话中出了什么问题，读取磁盘上的转录记录，并带着证据报告发生了什么。你负责报告；你不负责诊断 superpowers。由分诊该捆绑包或该问题的人来决定 superpowers 是否改动。

**核心原则：** 每项发现都引用 `path:line`。没有引用，就没有发现。每个数字都来自转录记录或你运行过的命令，绝不来自记忆。

## 工作流

每一步创建一个待办。第 5–7 步仅在各自声明的条件下运行。

1. **问题受理。** 一次问一个问题，直到你能写出一段陈述，说明涉及的会话、轮次范围（如已知）、你的伙伴期望什么、实际发生了什么，以及他们在意的可观测指标（实际耗时、token、重复动作、某个具体动作）。“太耗时了”是一句抱怨，不是问题陈述。记下目标是否为一份 superpowers bug 报告。
2. **定位。** 使用 `references/session-discovery.md` 将每个会话解析为经过核实的绝对文件系统路径。通过引用某个过往会话的首个提示词和时间戳来确认它，并列出每一个你排除掉的候选项及其原因，或写“无”。枚举子智能体转录。创建 `~/.superpowers/diagnosing-superpowers/<session-id>/`，把路径告诉你的伙伴，并在其中填写 `templates/case.md`，遵循其关于环境和技能观察的出处规则。
3. **分诊。** 你自己先阅读所报告问题附近的区域。然后按维度并行派发分析子智能体，每个都给出案例文件路径、`prompts/analyst-common.md`，以及 `prompts/` 中的一个维度文件：`skill-timeline.md`、`plan-adherence.md`、`repeated-work.md`、`stumbles.md`、`quality-evidence.md`、`request-conflicts.md`、`cost-and-time.md`。当转录很长时，按轮次范围拆分一个维度。丢弃任何没有 `path:line` 的返回发现。
4. **报告。** 按顺序填写 `templates/report.md` 的每一节，将其写入工作区，展示出来，并给出路径。核实所引用的内容实际能证明什么，并保留支撑案例；一个符号链接别名并非冗余副本。
5. **GitHub 问题** —— 当报告 §7 表示可能或很可能，或你的伙伴要求时。按 `references/github-issues.md` 搜索开启和关闭的问题以查找这些症状。展示匹配项，并建议把报告添加到最接近的那一个。如果没有匹配项，填写 `templates/issue.md`，写入工作区，展示确切文本，并在获得批准后才创建该问题。`gh` 无法附加文件；如果存在捆绑包，把它的路径给你的伙伴，以便在浏览器中附加。
6. **导出** —— 仅当你的伙伴要求捆绑包时；绝不在未被要求时构建一个。如果受理目标是 bug 报告，只说明一次：可应请求提供经过清洗的捆绑包，然后等待。询问脱敏级别，说明各自包含什么：骨架（不含工具结果正文）、证据（仅为被引用事件的正文）、完整。按 `templates/bundle-README.md` 构建捆绑包，派发 `prompts/scrub.md`，然后是 `prompts/scrub-audit.md`，重复二者直到审计返回 CLEAN。在展示最终的清洗日志、文件列表以及隐私与证据结果之前，完成捆绑包模板的证据检查和核对。仅在获得批准后才归档（`zip -r` 或 `tar -czf`）。拿到归档路径后，说明它包含什么，指出清洗日志以便查看替换项，并说明清洗可能遗漏内容：他们在分享前必须审阅每一个文件。
7. **相似会话** —— 当被要求时。把已确认的发现转化为一个特征签名，按修改时间和大小列出候选项，找出标记所在的行号，按候选项并行派发 `prompts/similar-session.md`，并追加报告 §9。

## 快速参考

全部七个分析始终都会运行。此表说明在第 3 步中你应自己阅读哪个区域，以及在结论中应优先以哪些发现开篇。

| 抱怨 | 优先阅读、优先展示 |
|---|---|
| “太耗时了” | cost-and-time、stumbles |
| “它为什么做这些额外的工作？” | repeated-work、plan-adherence |
| “为什么这么贵？” | cost-and-time |
| “它到底在干什么？”（仍在运行） | skill-timeline；在覆盖范围中注明进行中 |
| “它无视了计划” | plan-adherence，先看压缩行 |
| “技能 X 从未触发” | skill-timeline |

## 硬性规则

- **上下文安全。** 一行转录可能有一兆字节。每次处理每个会话文件时，都应遵循 `references/context-safety.md`。
- **只读。** 绝不修改、移动或删除会话文件。
- **给子智能体精确路径。** 子智能体的“当前会话”是它自己的。传递绝对路径和 id。
- **仅限人类提示词。** 钩子输出、系统提醒和工具结果不是你的伙伴的话。在子智能体转录中，“user”是父智能体。
- **不做 superpowers 诊断。** 报告 §7 说明参与情况后即停止。绝不在技能中指出缺陷或提出改动建议。你的伙伴催促修复并不免除这一点；指向问题步骤，并提到可应请求提供捆绑包。也不要向你的伙伴提供建议。
- **批准关卡。** 在你的伙伴看过清洗日志和文件列表之前，不得归档。在他们批准确切文本之前，不得创建问题或发表评论，也不得有占位摘要。
- **分析前先受理。** 在你的伙伴回答之前，第 2–7 步中的任何动作都不得开始。如果他们不在，写下问题然后停下。你为他们重建的陈述不算答案。一个已经限定范围的要求 —— 某个具体事件、当前正在运行什么，或要运行的分析 —— 本身就是该陈述：先回答它，然后提问。对整个会话问“为什么”则是一句抱怨。

## 危险信号

| 想法 | 实际情况 |
|---------|---------|
| “问题很明显，跳过受理” | 问题陈述界定了一切。要问。 |
| “他们不在，所以我来重建陈述” | 你无法重建他们想要什么。写下问题然后停下。 |
| “我现在把一切都扫一遍，最后再问” | 未经限定范围的扫描会把他们的预算花在错误的问题上。先问。 |
| “他们想要一份 bug 报告，所以我现在就构建捆绑包” | 捆绑包是他们的会话数据打包而成。仅在他们要求时才构建。 |
| “小小的针对性修改，不需要重构” | 无论多小，都不是你说了算。报告证据；由分诊者决定。 |
| “每个 token 的价格是众所周知的” | 你没有从转录中计算出来的数字都是杜撰的。要么引用，要么舍弃。 |
