## 入口流程

检查 `datadog-server-state`（见 `mcp-settings.md`）。使用插件的 Datadog MCP 服务器上的 `datadog://mcp/toolsets` 资源作为 MCP 调用（不要使用任何其他 Datadog MCP 服务器）。在 `datadog-server-state` 和资源内容可用之前，不要输出任何内容，并根据结果继续：

- **datadog-server-state=working** 且**内容有效** —— 不加任何前言，转到[工具集流程](#toolsets-flow)。
- **datadog-server-state=not-setup** —— 不加任何前言，告诉用户插件尚未设置，并指示他们运行 `/ddsetup`，然后停止。
- **datadog-server-state=not-working** 或**内容无效** —— 不加任何前言，告诉用户服务器已配置但无法工作，指示他们运行 `/ddconfig`，然后停止。

在下面与用户沟通时，用平实的语言描述服务器状态和操作。不要透露检查了什么、发现了什么，或任何实现细节，如文件内容或变量值。

## 工具集流程

工具集是某个特定 Datadog 功能的一组相关工具的命名分组。启用某个工具集即让其工具可用；禁用则移除它们。

### 工具集别名

工具集别名是一个名称，代表一组固定的工具集（其 `expandsTo` 列表）—— 例如某个工具集别名可能展开为 `logs,metrics,traces`。工具集别名与各个工具集来自同一个 `datadog://mcp/toolsets` 资源，每个别名都带有自己的 `expandsTo` 工具集名称集合。

服务器在凡是接受工具集名称的地方都接受工具集别名 —— 启用某个工具集别名即启用其 `expandsTo` 集合中的每个工具集，就如同逐个列出它们一样。这在两个方向上均有效：

- **展开** —— 用户指名某个工具集别名来启用/禁用/替换；将其视为其 `expandsTo` 集合中每个工具集的简写。
- **折叠** —— 如果得到的显式列表恰好包含某个工具集别名 `expandsTo` 集合中的所有工具集，就用该工具集别名来替代那些工具集，而不是逐个列出它们。

工具集别名是一种便利，而非单独的能力 —— 工具集别名绝不会授予任何其展开后的工具集未曾覆盖的工具。

### 工具集默认值的工作方式

注册文件中的 `X-Datadog-MCP-Toolsets` 头值控制哪些工具集处于活动状态。没有 shell 变量包装 —— 该值以裸字符串形式直接存储。它有两种状态：

- **空**（`""`）—— 由服务器决定启用哪些工具集。这是首选状态，因为插件会自动采纳服务器将来新增的默认工具集。
- **显式**（`"core,alerting"`）—— 恰好启用这些工具集，不多不少。服务器的默认值会被忽略。如果服务器之后新增默认工具集，此插件将不会采纳它。

逗号分隔列表中工具集的顺序没有意义。`core,alerting` 与 `alerting,core` 等价。在比较列表时（例如检查结果是否与默认值匹配），按集合比较，而不是按字符串比较。

在计算变更时，始终优先使用空值，而不是一个恰好与当前默认值匹配的显式列表。

### 1. 收集工具集信息

使用插件的 Datadog MCP 服务器上 `datadog://mcp/toolsets` 资源的内容。这会告诉你存在哪些工具集、当前启用了哪些、哪些是默认值、每个工具集的用途，以及有哪些可用的工具集别名（每个别名带有其 `expandsTo` 工具集名称集合）。向用户展示所有可用的工具集**以及**工具集别名 —— **不要**做汇总，并且**要**为客户端选择最佳格式（可选列表、表格、分组摘要等）。让用户容易识别当前启用了哪些工具集，以及有哪些工具集和工具集别名可用。

当某个工具集别名 `expandsTo` 集合中的每个工具集当前都已启用时，该工具集别名显示为当前已启用。

另外从注册文件的 `"headers"` 字段中读取当前的 `X-Datadog-MCP-Toolsets` 头值。如果为空（`""`），用户当前使用的是服务器默认值。如果是一个显式列表，那些就是手动选择的工具集。

注册文件中任何未出现在 `datadog://mcp/toolsets` 资源中的工具集名称都是未知的 —— 在向用户展示时忽略它，并在写入更新后的列表时静默丢弃它。

### 2. 理解用户意图

用户可能想要：

- 向当前启用的列表**添加**更多工具集
- 从当前启用的列表中**移除**工具集
- 用一组特定的工具集**替换**整个列表

从用户的回复中理解其意图。如果有歧义，请求澄清。

用户可能以单个名称或工具集别名来指代某个工具集。将工具集别名的引用视为其 `expandsTo` 集合中每个工具集的简写。

**重要：** 如果当前默认值为空（服务器默认值）且用户想要添加一个工具集，你需要知道默认值**是**什么，才能构建完整的列表。使用 `datadog://mcp/toolsets` 资源中的默认值信息。

### 3. 计算新的工具集列表

应用用户的更改，为 `X-Datadog-MCP-Toolsets` 头生成一个新的逗号分隔值：

- 首先，将当前工具集列表（来自注册文件）中发现的所有工具集别名以及用户指名的任何工具集别名（用于添加、移除，或作为替换列表的一部分）展开为其 `expandsTo` 工具集名称集合，然后针对该展开后的集合应用添加/移除/替换。
- 如果得到的列表与默认工具集完全匹配 → 使用空字符串（恢复为服务器默认值）。
- 如果用户想要恢复为默认值（例如“reset”“use defaults”）→ 使用空字符串。
- 如果得到的列表包含某个工具集别名 `expandsTo` 集合中的每一个条目 → 用该工具集别名替换这些条目。如果有多个工具集别名被完全覆盖，优先使用覆盖工具集数量最多的别名，然后对剩余的工具集重复此操作。
- 如果所有工具集都将被移除 → 使用空字符串，并警告用户将改用服务器的默认工具集。
- 如果得到的显式列表不包含 `core` → 在应用前警告用户。`core` 工具集提供关键的 Datadog 功能，大多数工作流都依赖它。只有当用户明确确认时，才在没有 `core` 的情况下继续。
- 否则 → 使用显式的逗号分隔列表。

### 4. 应用更改

直接在注册文件的 `"headers"` 字段中编辑 `X-Datadog-MCP-Toolsets` 头值。遵循 `mcp-settings.md` 中的编辑规则。

示例 —— 在当前使用服务器默认值时添加 `alerting`（假设 `core` 和 `synthetics` 是默认值）：

```
"X-Datadog-MCP-Toolsets": ""
  →
"X-Datadog-MCP-Toolsets": "core,synthetics,alerting"
```

示例 —— 恢复为服务器默认值：

```
"X-Datadog-MCP-Toolsets": "core,alerting"
  →
"X-Datadog-MCP-Toolsets": ""
```

### 5. 确认

告诉用户工具集已更新，包括现在启用了哪些工具集，并请他们按照以下步骤操作：

在 Antigravity 应用或 IDE 中：

1. 打开 Agent 设置（Mac 上为 ⌘,，Windows/Linux 上为 Ctrl+, —— 请显示当前操作系统对应的正确快捷键），然后转到 **Customizations**
2. 在已安装的 MCP 服务器下，点击刷新按钮
3. 如果提示，点击 `datadog-antigravity` 服务器旁边的 **Authenticate**，在浏览器中登录，然后把授权码粘贴到设置中并点击 **Submit**

在 Antigravity CLI 中：

1. 运行命令 `/mcp` 并重新加载 MCP 配置
2. 如果提示，对 `datadog-antigravity` 服务器进行认证
