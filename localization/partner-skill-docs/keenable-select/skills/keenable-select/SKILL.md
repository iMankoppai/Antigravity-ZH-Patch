# Keenable SELECT

本插件提供的 `select` 工具通过一条只读 SQL 查询，在实时网络搜索结果之上回答问题。服务器会执行搜索、抓取页面、用 LLM 提取查询所要求的字段、去重，并返回数据行。工具自身的描述就是查询方言的完整指南（带有 `WEB_SEARCH`、`WEB_FETCH` 和 `SEM_*` 函数的 DuckDB `SELECT`）：请阅读并遵循它。本技能介绍何时使用该工具，以及如何围绕它来与用户协作。

## 何时使用

- 答案是一个表格或列表："which X"、"compare X across Y"、"how many"、"every Z with its price / version / date / source"。
- 答案分散在许多页面上，一次搜索加几次页面阅读会遗漏其中大部分内容。

对于单一事实、某个已知页面或快速核对，普通搜索更快、更省。当答案的形态是数据行时，使用 SELECT。

## 工作流

1. 当问题含糊时，与用户确定列和范围：哪些字段、哪个时间范围、哪个地区、多少行。
2. 编写一条覆盖面广的查询：按工具指南所述，在 `WEB_SEARCH(...)` 中使用若干真正不同的搜索措辞，而不是同一个措辞的变体。
3. 告知用户一次查询需要数秒到几分钟。对于一次会搜索、读取并提取的调用，这属正常；不要把它当作卡死而取消。
4. 呈现表格及其来源。每次调用都会返回一个结果集 ID：对于同一数据上的后续追问（"only the ones under 30 EUR"、"sort by date"），在 `FROM` 中查询该 ID，而不是再次搜索网络。
5. 提取只反映页面上说了什么，并不对之进行事实核查。对于有重大影响的数字，跨独立页面进行交叉核对，并说明哪些行仅依赖单一来源。

## 报告

`generate_html_report` 根据一份简述和你指定的结果集构建网页，并返回其链接。任何拿到链接的人都能打开它。仅在用户要求可分享的报告时才构建，并在发布前说明这一点。`revoke_html_report` 在用户要求时撤下报告。生成一份报告需要数分钟，因此请基于聚合后的结果集构建，而不是基于数百行的原始表格。

## 账户与费用

该服务器需要一个 Keenable 账户。首次使用时，Antigravity 会打开浏览器登录；批准后即可使用这些工具。每次查询都会计费到已登录的账户。如果调用失败并返回 401，表示登录已过期：请用户重新对 `keenable-select` 服务器进行身份验证。若返回 429，稍等片刻后重试一次。绝不要要求用户将 API 密钥粘贴到聊天中。
