# 音频混音器设置

将音频源路由到混音器组是只有运行中的编辑器才能进行的场景编辑，因此本技能需要一个可在其中执行 C# 的实时编辑器。步骤 0 会在做任何其他事情之前确立这一点。

**本技能自动化什么，以及把什么交回给你。** 检查混音器并将音频源路由到组完全是公开的 Unity API，而这是繁琐的部分——遍历数十个源并按它们播放的内容进行分类。创建混音器或组没有公开 API；它只存在于 Unity 并不承诺保持稳定的类型上。因此本技能不会背着你在后台创建组。它会清点已存在的内容，提出路由方案，请你在 Audio Mixer 窗口中添加任何缺失的组，然后自己完成所有路由。

这是刻意的限制，而不是需要绕过的缺口。不要为了创建组而使用反射，也不要手动编辑 `.mixer` 文件——盲目编写混音器结构是不安全的。

## 步骤 0：确认你可以在编辑器中运行 C#

下面每个 C# 步骤都通过 Unity CLI 在实时编辑器中运行。**`unity-cli` 技能负责带你到达那里**——安装 CLI、确认已连接的编辑器、添加项目的 `com.unity.pipeline` 包、区分真正缺失的编辑器与卡在安全模式中的编辑器，以及发现编辑器的命令目录。先遵循它；不要在这里重新推导任何这些内容。

有两件事它无法替你了解：

- **你特别需要 `script eval`**，而不仅仅是一个可访问的编辑器。确认它出现在目录中。它的存在取决于 Pipeline 包版本，而不是 CLI，因此健康的安装仍可能缺少它——如果缺失，请说明并停止。
- **不要回退到手动编辑 `.mixer` 文件。** 盲目编写混音器路由是不安全的，因此无法访问的编辑器是停止信号，而不是随机应变的提示。

一旦 `script eval` 可用，下面每个 C# 步骤就以此方式运行。

通过 `script eval` 命令在已连接的编辑器中运行 C#。从 `unity command --format json` 发现其参数形态，而不要假设——内联形式为
`unity command script eval --caller plugin --skill audio-setup-mixers --code '<snippet>'`，某些 Pipeline 版本还注册了
`script eval_file` 以便从文件运行代码段。**在动用 `script eval_file` 之前先检查目录；它经常缺失。** `unity command` 默认超时为 30 秒。

### 将 C# 传给 `script eval`

`script eval` 编译的是**语句块，而不是文件**。由此产生两个后果，两者都会导致编译错误而非警告：

- **没有 `using` 指令。** 编译器会将 `using UnityEngine;` 读取为资源释放语句并拒绝它（`CS0210`）。
- **类型必须完全限定。** 裸的 `AssetDatabase` 或 `Volume` 无法解析（`CS0246` / `CS0103`），而裸的 `Object` 会与 `object` 产生歧义（`CS0104`）。

如果下面的代码段是以文件形式编写的——为了可读性带有 using，或因需要保存到项目中——在将其传给 `script eval` 之前请先限定类型。

## 步骤 1：预检
如果用户没有明确要求 Audio Mixer，请确认他们想要继续进行设置。

然后使用 [references/api.md](references/api.md) 中的 mixer-inventory 代码段清点已存在的内容，按步骤 0 所述通过编辑器运行。这会给你项目中每个混音器以及每个混音器中的组名称。

它返回的是组的扁平列表，而不是父/子树。这足以用于路由，而且它就是公开 API 所暴露的全部内容。如果层级关系对对话很重要，请让用户查看 Audio Mixer 窗口并描述它——不要为了查明而动用非公开的树 API。

**如果项目完全没有混音器，** 请说明并停止，而不是临时编造一个：创建混音器没有公开 API。请用户创建一个（Window → Audio → Audio Mixer，然后点击 Mixers 旁边的 **+**），一旦创建好就从这里继续。

## 步骤 2：查找场景引用
查找所有音频源（Audio Source）组件，查看它们所分配的 Generator 资产名称，并归纳出一个合适的类别或声音名称分类，理想情况下使用已经存在的类别。
音频剪辑资产名称的示例：
- "FootStep4_Sound" -> Foley
- "Dialogue_Female_Scene4" -> Vox/Voice/Dialogue
- "GunShot" -> SFX
- "Menu_Theme_Variation" -> Music

如果分配的资产不具描述性或不存在，请尝试查看 GameObject 名称或可能相邻的 MonoBehaviour 名称。
如果难以对音频源的使用方式进行分类，或信心较低，请要求创建一个 Uncategorized 组。

## 步骤 3：商定组列表，并创建任何缺失的组
将步骤 2 的分类作为提议的路由方案呈现——每个音频源以及你打算将其发送到的组——并与用户一起修订。

**在继续之前等待用户回应。**

当现有组确实涵盖该类别时，优先使用现有组，即使你会以不同的方式命名它。但**不要合并混音工程师会区分的类别**——Foley 是 SFX 的子集，而不是 SFX 的另一个叫法，因此枪声不应该仅仅因为存在一个 `Foley` 组就归入其中。当现有组只部分涵盖你的类别时，说明哪些合适、哪些需要新组，并让用户决定。

对于没有匹配组的类别，你无法创建组——没有公开 API 可做到这一点。请准确地移交，指明混音器和确切的组名称，如 [references/api.md](references/api.md) 末尾所示。然后在路由之前**重新运行清点代码段以确认这些组存在并检查其拼写**。不要假设用户已完成，也不要假设他们按你所要求的方式拼写。

## 步骤 4：路由音频源
组列表确定并确认存在后，使用 [references/api.md](references/api.md) 中的路由代码段为每个音频源的输出组赋值。它全程使用公开 API，并将整个处理过程包装在单个撤销步骤中，以便用户可以一次性全部撤回。

**以你分类时所用的标识符作为映射键。** 步骤 2 首先读取剪辑资产名称，仅在必要时才回退到 GameObject 名称，因此映射接受两者——二者是不同的标识符，以错误的那个为键会漏掉源。

有三件事要报告而非假设：

- **代码段返回的任何 `NO SUCH GROUP` 条目。** 这意味着你期望的组不在混音器中——通常是拼写差异。与用户一起解决，不要静默跳过该源。
- **任何 `NOT IN THE MAPPING` 条目。** 这些是你的分类遗漏的音频源。在源被悄悄留作未路由的同时报告路由成功是这里最糟糕的结果，因为它读起来像是成功。
- **被修改的是场景，而不是混音器资产。** 路由存在于音频源上，因此只有在场景保存后才会持久化。告诉用户，并仅在征得其同意后保存。

**音量、效果和重新父级化不在范围内。** 它们存在于非公开 API 上。如果用户要求这些，请说明路由已完成，并指向 Audio Mixer 窗口以进行混音本身。
