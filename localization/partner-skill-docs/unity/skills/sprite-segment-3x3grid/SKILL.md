# 精灵颜色网格分析

## 目的

本技能通过将精灵纹理分割为 3x3 网格，并根据与中心单元格的颜色匹配情况输出文本表示，来分析精灵纹理。

## 参数

### 匹配阈值

**匹配阈值**决定非中心单元格中有多少百分比的像素必须与中心的主色匹配，该单元格才被视为“匹配”（`.`）。

| 阈值 | 描述 | 使用场景 |
|-----------|-------------|----------|
| **50%** | 单元格至少一半的像素与中心颜色匹配 | 对混合区域的精灵采用宽松匹配 |
| **75%** | 至少四分之三与中心颜色匹配 | 对大部分为纯色区域的适度匹配 |
| **90%** | 几乎所有像素都必须与中心颜色匹配 | 对非常均匀的精灵采用严格匹配 |

**默认值**：75%

## 算法

1. **分割精灵**：将精灵的纹理区域划分为 3x3 网格（共 9 个单元格）
2. **识别中心颜色**：计算中心单元格（位置 [1,1]）中的主色（出现最频繁的颜色）
3. **比较每个单元格**：对于周围 8 个单元格中的每一个，计算与中心主色匹配的像素百分比。如果该百分比达到或超过**匹配阈值**，则该单元格为匹配（`.`）；否则为不匹配（`X`）
4. **生成输出**：使用下面的图例创建文本表示

## 输出图例

| 符号 | 含义 |
|--------|---------|
| `X` | 单元格未达到匹配阈值（匹配中心颜色的像素不足） |
| `.` | 单元格达到匹配阈值（匹配中心颜色的像素足够） |
| `*` | 中心单元格本身（始终位于网格中的位置 [1,1]） |

## 输出格式

输出为一行，包含三组三个字符，以 ` / ` 分隔。每组代表网格的一行。

**顺序**：从上到下的行，每行内从左到右。

**格式**：`[TopRow] / [MiddleRow] / [BottomRow]`

每行包含 3 个以空格分隔的字符：`[Left] [Center] [Right]`

### 网格位置映射

```
Grid Layout:        Output Order:
[0,0] [1,0] [2,0]   1  2  3   -> First group
[0,1] [1,1] [2,1]   4  5  6   -> Second group (5 is always *)
[0,2] [1,2] [2,2]   7  8  9   -> Third group
```

### 示例

**示例 1**：中心仅与左上和右下匹配
```
. X X / X * X / X X .
```
网格解释：
```
.  X  X
X  *  X
X  X  .
```

**示例 2**：中心与所有周围单元格匹配
```
. . . / . * . / . . .
```

**示例 3**：中心不与任何周围单元格匹配
```
X X X / X * X / X X X
```

**示例 4**：中心仅与底行匹配
```
X X X / X * X / . . .
```

## 实现指导

### 计算中心的主色

对于中心单元格：
1. 采样该单元格边界内的所有像素
2. 按颜色对像素分组（考虑对相似颜色使用颜色容差阈值）
3. 主色是像素数量最多的颜色
4. 对于平局，使用最先遇到的颜​​色

### 匹配非中心单元格

对于周围 8 个单元格中的每一个：
1. 统计单元格中的像素总数
2. 统计有多少像素与中心主色匹配（使用颜色容差）
3. 计算匹配百分比：`matchingPixels / totalPixels`
4. 如果匹配百分比 >= 阈值，则单元格为匹配（`.`）；否则为（`X`）

### 颜色容差

比较像素颜色时：
- 考虑为“匹配”使用容差阈值（例如 RGB 距离 < 10）
- 或者，对于调色板有限的精灵，精确匹配可能是合适的
- 如果与用例相关，考虑 Alpha 通道

### 精灵边界

使用精灵的 `rect` 属性来确定要分析的像素区域：
- `sprite.rect.x`、`sprite.rect.y` 表示原点
- `sprite.rect.width`、`sprite.rect.height` 表示尺寸
- 将宽度和高度除以 3 得到单元格尺寸

## 使用场景

- **文档记录**：以紧凑的文本格式描述精灵模式
- **测试**：在自动化测试中验证预期的精灵结构
- **分析**：快速识别具有相似颜色分布的精灵
- **调试**：理解精灵为何与预期外观不同
- **资产编目**：为精灵资产生成可搜索的元数据

## 说明

- 此分析最适合具有明显颜色区域的精灵
- 对于具有渐变或多种颜色的精灵，考虑提高颜色容差
- 为产生从上到下的输出，Y 轴相对于 Unity 的纹理坐标是翻转的
- 透明像素可以根据用例被视为一种独特的“颜色”或被忽略
