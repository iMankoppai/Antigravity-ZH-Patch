# 通过文件请求收集文件

使用此技能帮助用户通过 Dropbox 文件请求从他人处收集文件。

## 工具

- `create_file_request`
- `get_file_request`
- `list_file_requests`
- `create_folder`
- `get_file_metadata`
- `list_folder`

## 工作流

1. 确定用户是想创建新的文件请求、检查某个请求，还是列出已有请求。
2. 对于新请求，确定目标文件夹。
3. 不要将团队根目录（如 `/`）或用户的个人根目录（如 `/FirstName LastName`）用作目标位置。Dropbox 要求文件请求的目标是该文件夹下的子文件夹，例如 `/FirstName LastName/Invoices`。
4. 若所请求的目标位置是团队根目录或用户的个人根目录，请用户确认该文件夹下的子文件夹。
5. 若目标文件夹不存在且用户希望创建它，仅在明确确认后使用 `create_folder`。
6. 在调用 `create_file_request` 之前，确认标题、目标文件夹、截止日期（如适用），以及该请求应为开放还是关闭（若该选项可用）。
7. 对于已知的原始请求 ID，使用 `get_file_request`。
8. 当用户询问已有请求或无法确定某个请求时，使用 `list_file_requests`。
9. 创建或找到请求后，说明请求 URL 以及上传的文件将存放的位置。

## 需要确认

在创建文件请求之前，确认：

- 请求标题
- 目标文件夹，确认其为任何所请求的团队根目录或用户个人根目录下的子文件夹
- 截止日期（如请求）
- 工具支持的任何访问或开放/关闭设置

在创建目标文件夹之前，确认：

- 确切的文件夹路径
- 父文件夹是否已存在
- 该文件夹不是团队根目录（如 `/`）或用户的个人根目录

## 输出

返回：

- 文件请求标题
- 请求 URL 或标识符
- 目标文件夹
- 状态
- 截止日期（如有）
- 用户仍需执行的任何操作

## 安全

未经明确确认，不要创建文件夹或文件请求。不要假设上传的文件是私密或已审查的；清楚地描述目标位置和访问影响。Dropbox 不允许在团队根目录（如 `/`）或用户的个人根目录创建文件请求；请用户确认该文件夹下的子文件夹，不要用猜测的文件夹重试。

## 良好触发

- “为供应商发票创建一个 Dropbox 文件请求。”
- “做一个上传链接，让候选人提交作品集。”
- “显示我开放的文件请求。”
- “检查这个文件请求的状态。”

## 不适用场景

- 用户想共享现有内容。使用 `share-dropbox-content`。
- 用户想整理现有文件。使用 `organize-dropbox-folder`。
- 用户想恢复已删除的文件。说明在 Dropbox 恢复工具被暴露之前无法恢复。
