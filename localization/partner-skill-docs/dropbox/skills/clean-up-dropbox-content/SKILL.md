# 清理 Dropbox 内容

在 Dropbox 中使用此技能执行谨慎的删除工作流。

## 工具

- `search`
- `list_folder`
- `get_file_metadata`
- `list_shared_links`
- `copy`
- `delete`
- `check_job_status`

## 工作流

1. 确认清理目标和范围。
2. 使用 `search` 或 `list_folder` 识别候选内容。
3. 使用 `get_file_metadata` 核实每个删除候选。
4. 当删除共享内容可能影响他人时，使用 `list_shared_links`。
5. 若用户可能需要回滚上下文，请说明当前 Dropbox MCP 工具不提供版本列表或恢复操作。
6. 若用户希望先保留副本，确认确切的目标位置，调用 `copy`，并对任何异步复制任务使用 `check_job_status` 直到其成功完成。
7. 在所请求的复制成功完成后，呈现删除审查列表并请求明确确认。
8. 仅对确切确认的项目调用 `delete`。
9. 对任何异步复制或删除任务使用 `check_job_status`，直到其完成或必须报告为待处理。
10. 报告每一个已复制、已删除、已跳过、待处理或失败的项目。

## 需要确认

在删除任何内容之前，确认：

- 确切的路径或稳定标识符
- 每个项目是文件还是文件夹
- 该项目是否看起来已共享
- 为何删除是安全的
- 若用户希望先保留副本，确切的复制目标位置

## 输出

删除前，呈现：

- 候选路径
- 类型
- 修改时间（可用时）
- 共享状态（相关时）
- 若先保留副本的复制目标位置
- 看起来可以安全删除的原因

删除后，呈现：

- 已复制的项目（相关时）
- 已删除的项目
- 待处理的项目和任务状态（相关时）
- 失败的项目及原因
- 因模糊或有风险而跳过的项目

## 安全

切勿仅根据“旧文件”或“重复文件”之类的宽泛模式删除，而不列出确切目标。切勿在用户仅确认子文件时删除父文件夹。若信心不高，请停下来让用户选择。

## 良好触发

- “删除这些 Dropbox 文件。”
- “清理这个文件夹里重复的 PDF。”
- “移除过时的草稿文件。”
- “从 Dropbox 删除临时导出文件。”

## 不适用场景

- 用户想将内容移动到归档。使用 `organize-dropbox-folder`。
- 用户想恢复内容。说明在 Dropbox 恢复工具被暴露之前无法恢复。
- 用户只想要清理候选列表而不删除。使用 `find-dropbox-content` 或 `inspect-dropbox-file`。
