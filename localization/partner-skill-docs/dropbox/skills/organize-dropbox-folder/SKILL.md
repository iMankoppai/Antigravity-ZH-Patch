# 整理 Dropbox 文件夹

使用此技能通过创建文件夹、复制和移动来安全地整理 Dropbox 内容。

## 工具

- `list_folder`
- `search`
- `get_file_metadata`
- `create_folder`
- `copy`
- `move`
- `check_job_status`

## 工作流

1. 理解所需的整理目标和目标范围。
2. 使用 `list_folder` 或 `search` 盘点相关内容。
3. 对可能被移动或复制的项目使用 `get_file_metadata`。
4. 在任何变更之前草拟提议的变更计划。
5. 若需要，在确认后使用 `create_folder` 创建目标文件夹。
6. 当保留原始位置很重要，或用户说复制/克隆时，使用 `copy`。
7. 仅当用户明确希望内容被迁移或归档时，才使用 `move`。
8. 对任何异步复制或移动任务使用 `check_job_status`，直到其完成或必须报告为待处理。
9. 更改后，汇总所有已创建、已复制、已移动和待处理的路径。

## 需要确认

在任何变更之前，确认：

- 源路径
- 目标路径
- 操作是复制还是移动
- 是否应创建目标文件夹
- 操作后的预期结果

## 输出

变更前，呈现计划：

- 要创建的文件夹
- 要复制的文件或文件夹
- 要移动的文件或文件夹
- 需要澄清的项目

变更后，报告：

- 成功创建的文件夹
- 成功复制的项目
- 成功移动的项目
- 待处理的任务及当前状态（相关时）
- 任何失败或跳过的项目

## 安全

当用户意图不明确时，优先复制而非移动。未经额外确认，不要移动已共享的文件夹或高层团队文件夹。不要删除任何内容；仅在明确请求删除时使用 `clean-up-dropbox-content`。

## 良好触发

- “按客户把这些文件整理到文件夹里。”
- “归档去年的项目文件夹。”
- “把这些素材复制到发布文件夹。”
- “把所有最终 PDF 移到 Final 文件夹。”

## 不适用场景

- 用户只想搜索或检查内容。使用 `find-dropbox-content` 或 `inspect-dropbox-file`。
- 用户要求删除内容。使用 `clean-up-dropbox-content`。
- 用户要求恢复内容。说明在 Dropbox 恢复工具被暴露之前无法恢复。
